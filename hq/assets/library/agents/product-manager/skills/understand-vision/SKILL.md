# Understand Vision

Use this skill when the user asks you to define a product but hasn't given you full context, or when the brief feels thin or speculative.

## When to Use

- First conversation about a new product
- When the brief is missing or outdated
- When the user says something like "I want to build X" without detail
- When direction has changed and the brief no longer reflects reality

## Interview Protocol

Ask one question at a time. Wait for a real answer before asking the next. Do not infer or assume.

**Round 1 — The Goal**
1. "What does success look like in 6 months for this product?"
2. "Who is this for? Describe a specific person who would use or benefit from it."
3. "What problem are they experiencing today that this solves?"

**Round 2 — Constraints**
4. "What constraints are we working within? (time, budget, team size, technology)"
5. "Is there anything we definitely will not do? What is explicitly out of scope?"

**Round 3 — Success Criteria**
6. "How will we know we have succeeded? What does done look like?"
7. "Are there any existing solutions we admire or are inspired by?"

## After the Interview

Summarise what you heard and confirm:

> "Based on what you've told me: [2-3 sentence summary of goal, who it's for, and constraints]. Is that right?"

Only after the user confirms — use the `write-brief` skill.

## Rules

- Never write the brief before this interview is complete and confirmed
- If the user gives you a one-liner and asks to "just write the roadmap" — run this interview first
- Surface ambiguity rather than resolving it speculatively
- If the user cannot answer a question, note it as an open question in the brief rather than guessing
