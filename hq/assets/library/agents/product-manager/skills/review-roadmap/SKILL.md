# Review Roadmap

Use this skill when the roadmap is stale (more than 7 days since last update) or when a decision requires a roadmap review.

## Step 1: Read Current State

Read `ROADMAP.md` from the project's files, and the brief for the unit of work in hand (list `work/` if it is not already clear which unit). Note: what phase are we in? When was the roadmap last updated?

## Step 2: Assess

1. Are the current phase targets still realistic?
2. Have any milestones been completed? Should they move to Story So Far?
3. Has anything happened that changes the plan?
4. Is the brief still accurate?

## Step 3: Decide

**Minor updates (do directly, no user approval):**
- Updating dates that have slipped
- Rewording a deliverable to match what was actually built
- Archiving a completed phase into Story So Far
- Adjusting the Current phase to match current reality

After making minor updates: write the update to the project's files and add a comment on the relevant project: "Roadmap updated: [what changed]."

**Major changes (raise to user first):**
- Adding or removing phases
- Changing the scope of a milestone
- Dropping deliverables
- Any change that materially affects the Project Manager's plan

For major changes: add a comment with "Roadmap review needed: [what changed]. Proposed change: [options]. Please confirm before I update."

## Rules

- Never silently rewrite a roadmap that changes scope — the user must approve scope changes
- If unsure minor vs major: treat it as major and ask
- Always read the brief before touching the roadmap
