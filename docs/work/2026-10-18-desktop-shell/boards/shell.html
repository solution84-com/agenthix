1 · Today's shell (the chat-first redesign)

Every place is its own screen: Chat (your space) or a project. The main pane is that place's conversation list, or one conversation that replaces it; the right pane is the Tools panel (tasks, boards, timeline, runs, settings). There is no docked conversation, so leaving a place leaves its conversation.

2 · Proposed shell: the canvas for work, one conversation docked

On the right, a docked conversation shows only the conversation you have open, with its place on a chip. Moving around the canvas never changes it. The full Chat view stays the one place to find conversations.

4 · Project → its conversations, and a new one

Superseded (walkthrough 2): a new conversation is now a draft in the dock, chosen from the list of places, with Cancel — see new-conversation.html. This section is kept as drawn.

On a project, 💬 Talk about Agenthix in the bar starts a new conversation in that project and puts it in the dock. The ＋ in the dock does the same. A new conversation asks for nothing: two chips above the message box are already filled in — the place (the one you're looking at) and the agent (that place's default: the project's default agent, or your primary agent in your space) — so you write and send. Either chip can be changed before the first message; changing the place resets the agent to that place's default if the one chosen can't work there. The coordinator brings in other agents as the work needs, so the agent chosen is who leads, not the only one who can help.

One rule at every width: you have one open conversation and it never closes by itself. What changes with width is only whether it sits beside the work or over it. Resizing a window moves between these without losing anything — the same conversation, scroll position and unsent text.

7 · Questions — all answered

The issue's five and two more, each answered on 2026-10-17. The Agreed list is the record.

1. How is the open conversation shown and switched, without a second chat tree?

A title and place chip in the dock's head; 🕘 opens a short recent list and All conversations (the full Chat view).
🕘 recent list + All conversations agreed
Only via the Chat page
Tabs of open conversations in the dock
Why: switching is frequent, so one click from anywhere; the list is flat and short, so it doesn't become a navigation tree. Tabs grow into exactly that.

2. On a project: a new-conversation shortcut, a list shortcut, or both?

Both — 💬 in the bar, and a Conversations tab agreed · owner's suggestion
New only
Why: the tab is today's project list, moved — nothing new to build, and it's where people look for a project's conversations. The Chat page keeps the place filter for everything across places; both open into the same dock, so there is still one open conversation.

3. What happens to the open conversation when you move between projects or to settings?

It stays; its chip shows where it lives agreed
It switches to that project's last conversation
It stays, with a nudge to start one here
Why: the issue rules out automatic context switches; the chip makes a mismatch visible, and the bar's 💬 shortcut is the explicit way to start one about the place you're on.

4. How do the dock and the Chat page share selection, and what does collapse do?

One selection; collapse keeps it, rail shows activity agreed
Chat page opens conversations in the canvas, separate from the dock
Why: one "open conversation" per person is the simplest model — choosing in Chat opens it in the dock, the URL carries it (?c=) so reload and back work, and a collapsed dock still shows work under way and approvals waiting.

5. Is a focused project mode needed?

No mode — ⤢ expands, › collapses; expanded gives way when you go somewhere; test first agreed
Yes, a focused project mode
Why: expand and collapse cover "conversation only" and "work only" with no new mode; the issue makes the mode optional, so it waits for testing.

6. (New) Today's Tools panel on a project — tabs in the canvas, or keep the panel?

Tabs in the canvas agreed
Keep the Tools panel beside the canvas
Why: with the dock on the right, a second right-hand panel leaves the work squeezed between two panels; tabs give boards and timelines the full width. Same views, moved — shell-only.

7. (New) On narrower windows — one model at every width, or a separate conversation-first phone layout?

One model: beside on wide, over on medium, a pill on narrow agreed
Keep today's place screens on phones
Why: two models mean two sets of behaviour to learn and to build, and resizing a desktop window would jump between them. One rule — the open conversation never closes — holds everywhere; only its position changes. The phone app (Flutter) is separate and unaffected.

Agreed

  • The open conversation always stays, wherever you go on desktop: other projects, Tasks, Settings, Home. Nothing switches it but you (owner, 2026-10-17).
  • A reply keeps streaming, and voice keeps going, wherever you navigate. The dock sits in the shell above the routes, so its subscription and the streaming reply stay mounted while the canvas changes; expand, collapse, slide-over and pill move it, never remount it. A reload rejoins with the running reply replayed, as the thread does today. Voice already carries on across pages through the shell's voice bar (owner, 2026-10-17).
  • A new conversation asks for nothing: place and agent are chips already filled in (the place you're on; its default agent, or your primary agent), changeable before the first message (owner, 2026-10-17).
  • No focus mode. ⤢ expands the conversation for reading and writing; going anywhere drops it back to docked, so it never hides where you went. › collapses it (owner, 2026-10-17).
  • A project's tools are tabs across the canvas — Overview · Conversations · Tasks · Boards · Timeline · Runs · Automation · Settings — the same views, given the full width. The Tools panel and the four-way layout control go; the dock's expand and collapse cover them (owner, 2026-10-17).
  • One open conversation, always in the dock: the Chat page and a project's Conversations tab both open into it, never into the canvas; it is in the address (?c=) so reload, back and links keep it; collapsing keeps it, the rail showing work under way and approvals waiting. People always know where the conversation is (owner, 2026-10-17).
  • Switching is a history icon (🕘) in the dock: your recent conversations, each with its place chip, and All conversations for the Chat page. No tabs (owner, 2026-10-17).
  • One model at every width: beside the work when wide, over it when medium, a pill when narrow; resizing never loses the conversation (owner, 2026-10-17: "it's consistent").
  • A project's conversations are a Conversations tab in its canvas, and 💬 in the bar starts a new one (owner, 2026-10-17).
