1 · Steps: today and after

Today (own-keys path): six

1 You2 Your organisation3 How agents reach AI: Cloud, your own keys, or later4 Model provider5 Voice6 Last look

Today the vendor for models and the vendor for voice are separate steps, the model default is chosen silently and only shows on the last look, and the key form never says where a key comes from.

After: four

1 You2 Your organisation3 AI4 Last lookChoiceModelVoice

  1. 1Your providers: every provider the organisation has, with chips for what it covers and its state. "None yet" when empty.
  2. 2＋ Add a provider: the only way to add one, in every state.
  3. 3What agents use: the model, hearing and speaking defaults the organisation starts with. Today's "Defaults for everyone" on the last look moves here.
  4. 4Skipping is never blocked (ADR-0160): a person can finish setup with no provider and no key, to look around. It is not recommended, so the last look says what stays off. Skip for now shows while nothing works; once a provider works the same place reads Continue. A type nothing covers reads "Not set", as in D, and is not an outage.
  5. 5The pop-up is the existing add-provider dialog, shared with Manage › Providers; one list of vendors for both. The type question ("what does the provider do?") goes: the chips say it. Agenthix Cloud is an entry, behaving as today's Cloud choice (a short-code approval, and greyed Not available yet until Cloud offers it). Inworld is listed like the others, with no price, plan or limit.
  6. 6Chips say which of models, hearing and speaking the provider covers, so one key covering three is seen, not promoted.
  7. 7Chosen for the person, changeable: set the moment a provider that serves it works, never overwriting a choice the person made. Change opens a searchable list. The model is the newest of a named family (see 5).

Why: the first draft listed vendors inline and then used a link once one was added, so the screen changed shape. One list, one button and one pop-up keep it the same in every state.
