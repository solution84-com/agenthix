C1 · Correcting a page by asking

The first way to correct knowledge: say what is wrong in a conversation. The agent finds the page, changes it, and the conversation shows the change with Undo.

  1. The person names the page (Mention from the page, or just its name; the agent uses search_knowledge).
  2. Updated page is a work step like the others, with what changed in one line. The agent changed one passage with edit_knowledge, through the gate.
  3. See change opens the page's history at that version (U4); Undo restores the version before it, for that person only if they may edit.

When the agent changes knowledge, and when memory

The person saysThe agent
"The release process page is wrong: …"Changes the page (a correction of a page)
"Write down how we deploy, for the team"Saves a new page (asked to)
"I prefer short answers"Remembers it (a preference: memory)
Nothing; the agent noticed something while workingRemembers it; may suggest "shall I add this to the project's knowledge?"

This is the rule in the Knowledge section of the prompt (board 5). No approval step: the person asked, and every change can be undone.

Why

  • Asking comes first: people correct in the conversation they are already in.
  • No approval step for a change the person just asked for; an approval would ask them to confirm their own words. History and Undo are the safety.
  • The change is shown in the conversation, so a misunderstanding is caught at once.
