Questions and decisions

The questions raised while designing, how each was decided, and the defaults the design applies. The spec is written from these boards.

Status

  • Boards: architecture 1–7; the Knowledge tool U1–U5; in a conversation C1–C3. Designed 24–25 Oct 2026; every question answered.
  • Today (boards 1 and U1) is read from main at 68bab23b.

Open questions

None. Every question is answered; see Decided.

Decided

DecisionWhen
Q1One way in for every agent, no skill.25 Oct
Q1bSearch is a grep (option C): a regular-expression search and a read, the same for the lead and workers; chosen for consistency and an answer in the same turn. Rejected: word matching (weak), handing the question to a worker (a container and a second model run), the glossary in every prompt (tokens on every turn), search by meaning (later, on top). Run safely: board 3, S1–S8.25 Oct
Q2Agents reach knowledge only through the knowledge tools: no knowledge folder in runs; the tools are shaped like the native ones and run on universal file tools. Settled while drawing boards 4–5.25 Oct
Q4Who may edit a project's knowledge: anyone who may change the project's files (assertLocationAccess(…, 'write')), the same people who can change its AGENTS.md. The same for a person's own space: the person.25 Oct
Q5Who may change organisation knowledge: organisation admins, and agents acting for one (the person a turn answers, or a run is for, is an organisation admin). Every member and every agent reads it.25 Oct

Recommended defaults

DecisionBoard
D1Platform knowledge is the user guide (docs/guide/), not the concepts docs; nothing is written twice.3
D2A new guide page, Glossary, lists each word, where it is (with its hq address), and what else people call it. The guide's rules gain: new words go in it.3
D3A tools reference is generated from hq's tool registry at build; never hand-written.3
D4Built by a stage of hq's image (the release rehearsal and the Release build make it; hq's dev start runs it too) into hq/assets/platform-guide/, which hq serves. hq's image parts gain docs/guide/ as an input, and a guide change selects hq's checks.3
D5Nothing about platform knowledge in the prompt. When to look it up is search_knowledge's description; "the guide grants nothing" heads every result. Revisited if V1 fails.3, 7
D6Knowledge is a place's own guide: anything shared across the project's workspaces (processes, decisions, reference), not opinionated. Pages are Markdown in any sections; front matter title, description, tags, plus any properties of the team's own (status, date…). No INDEX.md; old folders ignored.4
D7Limits: title 120, description 300, 8 tags, 20 properties, 64 KB a page, sections 8 deep, 2,000 pages. No attachments: pages link to Files.4
D8One gate for every change, agent or person: applied to the current page, the result checked (problems listed), a changed page refused, swapped in by one rename, who recorded. No drafts.4
D9Versions are whole earlier pages: 30 days and the last 20 always; deleted pages 30 days; 200 MB per place; delete permanently at once. Not git.4, U4
D10Five tools (search_knowledge, read_knowledge, write_knowledge, edit_knowledge, delete_knowledge), the same for the lead and workers, with no place parameter. No list tool: an empty search gives the sections and tags; results come 50 at a time.5
D11recall stops searching knowledge.5
D12search_knowledge runs ripgrep on every level, the program Claude Code's Grep runs, with S1–S8 from the same core module (the site's and hq's images gain the ripgrep package). RE2 dropped: ripgrep's engine has the same protection against runaway patterns. Ranking by meaning waits. The rules for writing a page are the tools' descriptions and refusals, not a skill (the lead has no skill loader); a team's own conventions go in its AGENTS.md.5, 7
D13Agents change knowledge when a person asks or corrects a page; no approval step; Undo in the conversation.C1
D14No check on briefs; the person sets the blast radius. A conversation reaches its own place, the organisation and the guide; other places only when the person adds them (C3, like Claude Code's additional directories). start_work and the knowledge tools reach only the conversation's places; the lead may suggest a place, never add one. Fingerprinting rejected as too complicated. Part of this unit, though it changes conversations.6, C3
D15Answers about Agenthix link to the screen in hq, not to the website.C2
D16Out of this unit: caching, ranking by meaning, usage measurement, organisation-wide knowledge, copy to project, review of agent-written skills.7
D17No product name in identifiers, so a rebrand changes no code: the guide is the platform: level of the knowledge tools, its files hq/assets/platform-guide/. The product name appears only in text people read.3
D18Every knowledge and guide tool is shaped exactly like the native tool agents are trained on: search_* like Grep, read_* like Read (lines, offset, limit), write_knowledge like Write (the whole Markdown, read first), edit_knowledge like Edit (old_string, new_string, replace_all; exact match). Built on Agenthix's own file tools (ADR-0085), lifted into core; the OpenCode plugin keeps its own shape on the same module.3, 5
D19Universal file tools underneath, lifted from the OpenCode plugin's own file tools (ADR-0085) and extended: @agenthix/core/file-tools (node-only) holds grep (ripgrep), read, applyEdit and write over any root folder, with the guards S1–S8 built in. The knowledge and guide tools are thin wrappers that pick the root, and the gate for knowledge changes. Ready for a runtime of our own later.5
D20Four levels: platform guide, organisation, project, person (a person's space and personal projects work exactly like a project). Organisation knowledge is stored like a project's, on the organisation's default site, placed at first use as a person's storage is. Tools take scope: "place" | "org"; search covers both by default. Pages link to each other: relative links between pages, broken links listed as problems, "Linked from" on a page.4, 5, U3, U5
D21One search over every level. search_knowledge covers this place, the organisation and the platform guide at once; each hit is marked place:, org: or platform:, which is also the page's name for read_knowledge; scope only narrows. The most specific wins: place, organisation, platform. No separate guide tools; the prompt's Knowledge section is five lines.
