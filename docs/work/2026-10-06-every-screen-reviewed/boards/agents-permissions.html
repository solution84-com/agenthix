Agents — permissions

What an agent may do, and where it is set. The organisation sets each agent's permissions (admins); a project may narrow them for its own runs (its admins); a person may narrow them for their own Chat. A narrower level can only take away, never add. Model access is not part of this — it is which model logins exist, reviewed with Settings.

Notes

Agreed

  • An agent's permissions get their own section on its page under Organisation, out of Settings (owner, 2026-10-09)
  • A project's agents list: the whole row is tappable (owner, 2026-10-09)
  • Model access is not an agent permission; tool risk rules wait for the Settings pass (owner, 2026-10-09)
  • In a list, the whole row opens the agent or person; the profile card opens from a name or picture in a conversation, a task or a run (owner, 2026-10-09)
  • The organisation, a project and a person see the same permissions view: every tool, Always · Ask · Never, command patterns. A project or a person is offered only the organisation's choice and stricter ones — Always: Always, Ask, Never; Ask: Ask, Never; Never: only Never. Looser choices are not shown. The project's and the person's narrowing store the same shape; the strictest level wins. Replaces today's checkbox list and typed tool names (owner, 2026-10-09)
  • Approval replaces "autonomy": when a person is asked about a tool set to Ask — Bypassed (every tool runs, including Never; no one is asked), Deferred (carries on, lists every Ask for the end), Immediate (stops at the first Ask and asks at once). Not "run mode" or "permission mode": it is about when a person approves; not "Blocked", which is a task's state. It comes first in Permissions; with Bypassed the tool list is not shown. Bypassed is the dangerous choice: its card is marked as a warning, saving it asks for confirmation, and wherever approval is summarised (the agent's page, Organisation › Agents) a bypassed agent carries a warning mark. Not "Not needed" (sounds safe) or "Waived". The same at every level; a project or a person is offered only the organisation's approval or a stricter one (owner, 2026-10-09)
  • When the organisation bypasses approval and a project or a person sets Deferred or Immediate, every tool shows Organisation: Bypassed and starts at Always (owner, 2026-10-09)
  • A project and a person also start from a preset — The organisation's, Safe, Read only, Developer, Project manager, Product manager — applied within the organisation's: each tool takes the stricter of the preset and the organisation. Like each tool, the organisation's approval is shown under the approval choices (owner, 2026-10-09)
  • Chat's Agents fact opens the organisation's agents in Chat's panel; one agent there shows Your permissions in Chat (k5) (owner, 2026-10-09)
  • Bypassed switches off the agent's own permissions for every tool, platform tools included — no hidden list applies while bypassed. What an agent does in Agenthix is still limited by the authority of the person the run is for: hq refuses anything that person may not do (a run nobody is behind can do nothing administrative). The card adds: What it does in Agenthix is still limited to what the person it works for may do. (owner, 2026-10-09)
  • A command matching no pattern follows Any other command — Always runs it, Ask asks, Never refuses; presets set it to Ask (owner, 2026-10-09)
  • The Unrestricted preset is dropped: presets only fill in the tool list; bypassing is approval Bypassed alone (owner, 2026-10-09)
