D is the proposal: the card the person answered is the record, folded to one summary line like the work line and opened to the same card in its answered state. A, B and C are kept small and greyed.
  • 8 The request: "Agent requests extended access", then "Additional tools" and "Bash prefixes" with the agent's reason; Approve / Reject tinted green and red; Reject asks an optional reason. A conversation's request carries no summary: the reply above it explains. Restored on reload while it waits. ManifestApprovalBubble.tsx; site server/runtime/deferredManifestReport.ts
  • 9 Once answered: a line in your column, "Manifest approved — agent is running" or "Manifest rejected — reason", stored as a special message of yours. SessionMessages.tsx UserMessage, __MANIFEST_APPROVED__
  • The spec says Reject here (§5) and Deny in Notifications and Runs (§6). Under §9 a run never waits: what needs approval is refused and listed, the run ends, and approving starts the next run with that alone allowed.
Why
  1. Plain words: who needs what to go on, each item as what it will do and why — no "manifest", "extended access" or "Bash prefixes".
  2. Approve / Deny, the same words as Notifications and Runs, where the same request also appears.
  3. No state colours on the buttons: Approve is the main action, Deny the other.
  4. The card the person answered is the record — the same thing, folded, so nothing new to learn; it sits in the run's flow like the other folded lines. It is not a message of yours you never wrote. It names who answered: in a shared project conversation that may be another member, or the person from Notifications.
  5. Opened, the card shows what was allowed in plain words, for how long, and a link to the run.
  6. The request ends a run and the answer starts the next, so the answered card sits between two work lines, in the order it happened.
  7. A request nobody answered says so once a newer message replaced it (§9), instead of vanishing.
  8. "Approving starts the next run" tells the person what Approve does under §9.
