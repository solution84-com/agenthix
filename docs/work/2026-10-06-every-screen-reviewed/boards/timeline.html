2A start date and a finish date — agreed. One thing to decide about the start

A · One start: the start time that starts the work

Today's start time does double duty. Dragging a bar's start moves when the agent begins. Simple, but planning a task for next week also schedules its run for next week.

B · A planned start, apart from the start time

The timeline's bar runs from a planned start to a finish by. The start time that starts the run stays its own setting, shown as a small marker. Planning moves no work.

4What "runs inside a bar" means

A · Plain bars

A bar spans from when work on the task began to when it was done. It does not say when the agent was actually working.

B · Runs as slices

Inside each bar, a darker slice for every run — the hours the agent actually worked. The gaps are waiting: for you, for its turn, or for the next day.

5The time scale it opens on

Week

Three weeks across, one column a day. Best for a sprint and for what agents are doing now.

Month

Three months across, one column a week. Sprints side by side; single tasks get thin.

Quarter

Two quarters across, one column a month. For a roadmap; individual tasks are hard to read.

Plan, schedule and work — three layers on one bar (proposed, from your answer to 4)

One task, three layers

Plan — the bar: the task's start and finish dates. Dragging the bar moves only the plan.
Schedule — ▶ markers: when the agent is set to start (the task's start time, or a routine's round). Dragging a marker moves when it starts.
Work — the dark slices: the runs that happened. Several runs can fall inside one plan.

A routine on the timeline

A routine stays its own thing (adr-0092): each round is a task it creates. On the timeline its row shows the rounds as ▶ markers; a round that has been created becomes a task with its own plan — by default its round's day — and its runs inside it.

Task types — epics for the longer view (proposed, from your answer to 5)

Month · epics only

An epic is a task that groups other tasks — "Pricing page", "Launch". Month and Quarter open on epics; each bar spans its tasks' plans. Opening one lists its tasks.

Week · tasks, grouped by epic

Week opens on tasks. A Show ▾ filter switches between epics, tasks, or both, in any scale.

Quarter — what a strategic view shows (a year across)

A · Epics only

The year as epics. Nothing new to model, but a year of epics is a long list, and nothing says what they are for or which ones matter by when.

B · Milestones, with epics under them

A milestone is a dated goal — "Self-serve pricing live", "1.0 launch". Each epic can belong to one. The quarter view shows milestones as ⚑ on their dates and folds each one's epics under it: what we commit to, by when, and what delivers it. One new thing, no deeper hierarchy.

C · Themes above epics

A theme (or initiative) is a long-running direction — "Grow self-serve", "Reliability". Epics belong to a theme; the quarter view is a lane per theme. A third level of hierarchy: more to keep tidy, and themes rarely end.

Strategy across several projects — a product's or a programme's roadmap — is the organisation's level (products and programmes group projects, adr-0061). That would be its own pass; this one is a project's timeline. The project's ROADMAP.md in Files is the written form of the same thing.

First draft — the views the choices refined

Boards say where work is; a timeline says when. A person comes here to see what happened and what is coming — sprints, what agents worked on and for how long, what starts later, what is due — across the whole project or for one board. It is one view drawn two ways: the project's Timeline tool, with a lane per board, and a board's own Timeline, switched with its columns.

How it works with the boards
  • One view, two scopes. The project's Timeline shows every board as a lane (Project Tasks first), each folding away; a board's Timeline is the same view with only that board, its sprints as bands.
  • A bar is a task. Clicking it opens the task inside the tool, as everywhere. Its colour says its state; a task that needs you is outlined.
  • Moving a dashed bar moves its start time (and its end, the finish-by date, if question 2 is agreed). Bars of work already done do not move.
  • Backlog is not on the timeline — it has no time yet. A board's Backlog count sits beside its lane name.
  • Narrow and on a phone it becomes an agenda: This week · Next week · Later, each line a task with its date.
