Tool — Tasks

The work in a project, and the work done for you. A person comes here to act on what needs them, to see what is being worked on and what is next, to open one task and see where it stands, and to add or place work. Most work is still asked for in the conversation; Tasks shows its state. The backlog is a view inside Tasks.

Comments and the session — which is for what

Comments — the task's discussion

  • Kept for good, short, written to be read later by someone who wasn't there
  • People talk to each other about the task, and leave direction for the agent's next run
  • The agent posts what each run did and where it got to, or asks for something it needs
  • Everyone with the task sees them; the agent reads them at the start of each run
  • Shown in full on the task

The session — the agent's working record

  • Everything the agent did: messages, commands, results; one per task, runs as dividers
  • Verbose, read when you need the detail
  • A person steps in to direct the run now: "approve it, but use staging"
  • Tool approvals sit here, where the agent stopped; the task shows the waiting one
  • Behind "Open session"; the task shows only what waits in it

Rule of thumb: if it should still matter tomorrow, or to someone else, it is a comment. If it steers the agent right now, it goes in the session.
