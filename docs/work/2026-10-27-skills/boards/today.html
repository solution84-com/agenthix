1 · Today: where skills live, how they reach a run

How skills work in hq and the site now, before any change. The numbers in the diagram match the table below.

The path today

What each box is

1Library skills

18 SKILL.md folders in hq's image (hq/assets/library/skills/), seeded into the Skill table at start, scope PLATFORM. Shown on the Library's Skills tab.

2Skills made here

Made in the Library by an administrator, kept in hq's storage under org/skills/, scope ORG. They can go to the organisation, but not to one agent.

3The organisation's package

A copy of each installed skill, with installed_from in its header. On its first write it gets every library skill, so every agent has all 18. Nothing in the interface removes one.

4An agent's package

A copy of each skill installed for that agent, or written on its page. Library skills only. Update shows when the library is newer.

5A place's files

A project's or a person's own storage: .agents/skills/ for every agent working there, and .agents/agents/<id>/skills/ for one. Plain files. Anything that can write files, an agent included, adds a skill here.

6Staging, per turn

The site copies all five sources into a fresh folder, as <source>-<slug>. Each header is rebuilt from an allowlist, links are refused and the reads are bounded (adr-0084).

7The runtime

Claude: a local plugin, a name allowlist and the Skill tool. OpenCode: the list goes in the system prompt, and Agenthix's plugin replaces the skill tool. The model sees each skill's name and description, then loads the body when the task matches.

8The conversation

A typed /name goes through untouched. A step reads "Used the skill org-dev-code-review", with the staged name, and opens nothing.

What already works, and stays

  • Staging per turn (box 6) works on both runtimes. A skill edited since the last turn is picked up on the next one, with no restart.
  • Safety in staging: a rebuilt header, no hooks, no inline shell, no links, bounded reads, and a read-only folder in the container.
  • Content by fingerprint (adr-0072): a run records exactly what it received.

The design changes what goes into staging and how people reach it, not staging itself.
