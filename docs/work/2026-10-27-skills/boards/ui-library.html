  1. In the sidebar, for everyone (D21), after Tasks and Agents (D26: Home, Chat, Your space, Projects, Tasks, Agents, Library). It replaces the Overview card and the /skills redirect. Members read; administrators and Library maintainers act (D28).
  2. Each row shows its type, identity and version (skill · publisher/name · version, D10), and who signed it: Signed by Agenthix, Signed by Acme (github.com/acme), Unsigned, or Made here (D8, D9).
  3. Who has it (D23): Every agent has it, named agents, or No agent has it yet. Built-in skills show a switch instead (D6). A template says what it brings and which agents or projects were made from it.
  4. Status, in words: Update available · 1.4 (V2), Draft by Sam (D24), Waiting for review (R1), Set aside (D18), Unsigned.
  5. Type is a filter, not a tab (D26). One search covers every asset; the type chips narrow it.
  6. Show filters by status: waiting for review, update available, draft, no agent yet. Proposals are rows with Waiting for review, not a tab of their own.
  7. Add opens the sources (U4) and New skill (U3b). Library maintainers see New skill; installing from outside stays with administrators unless the organisation allows maintainers (R2, P3).
  8. Marketplace is a button that opens its own page, behind a feature flag: on in development only, off in production, and refused by the server too, until it is built later (D26, adr-0116).
  9. Settings opens the organisation's settings (R2).

Before, after, why

Where it lives

Before

An Overview card and a redirect from /skills (U1 ①). Labelled "Ready-made things to start from".

After

A sidebar entry, Library, after Agents; Tasks moves before Agents because it is used more (D26). Described as what the organisation has installed. /skills opens the Library filtered to skills.

Why: people didn't find it (T1). One home for the one asset layer (D20, D21).

One view, filtered by type

Before

Tabs: Agents, Boards, Skills, Teams and Marketplace (Coming soon).

After

One searched list of every asset, with Type chips (skills, agents, boards, teams) and Show chips for status. No Marketplace tab: a Marketplace button, shown only in development (D26).

Why: every kind shares one layer (D20), so they share one list, one row and one set of statuses. A search across everything finds a skill and the template that brings it together. The marketplace is designed for later and must not appear in production (adr-0116).

A row

Before

Name, description, Built in or Made here, and Use, which only opens a dialog.

After

Type, name, identity and version, signer, who has it, and status. The row opens the asset's page (U3). The ⋯ menu has Add to agents…, Edit (U3b), Export and Remove, for those allowed.

Why: the row answers "what is it, who vouches for it, who has it, is it current" without opening anything. Use said none of that.

What a member sees

Before

The same list, with no Import or New. The dialog is read-only.

After

The same list, with no Add, Settings, switches or Add to agents…. A Library maintainer (D28) sees Edit, Publish, Update and Roll back on every asset. Any member can propose a skill: their New skill becomes a proposal (D27).

Why: reading answers "what can our agents do?" for everyone. The actions follow the role rules (D17, D27), checked on the server for every role and action.
