4 · The model: everything decided, in one picture

Redrawn 27 Oct from boards 2–3 and decisions D5–D16. Two worlds: installed skills, which hq holds, pins and versions, and skills in files, which their owners hold and hq observes and switches. Numbers match the diagram.

The picture

The parts

1Sources: anywhere

hq's image (Agenthix's packages), an upload, a URL, later a git repository or a hosted registry. Agenthix isn't prescriptive about where a skill comes from (D7).

2The check

The package ZIP, the fingerprint, a Sigstore signature, and four states: trusted, new publisher (asked), unsigned (warned), tampered (refused). The signer is an organisation; a person's signature is labelled as such (D8, D9).

3Installed skills

Held by hq for the organisation. One per identity (publisher/name), de-duplicated when installed (D10). Pinned to a version, with explicit update and roll back and a kept history (D11). Packages are self-contained: a template brings its role skills inside it.

4Given to agents

An installed skill is given to every agent (the organisation level, L2) or to chosen agents (L3). A template's role skills are given to the agent made from it. Built-in skills (L1a) are on for every agent, can be switched off, and are never edited.

5Skills in files

A place's files/.agents/skills (L4), one agent's folder there (L5), and each workspace's repository in all three folders (L6). Owned by whoever owns the files; their version is their content (F1–F3).

6Listed and switched

The site reports each skill folder and its fingerprint, and hq lists them on the place's Skills page. The organisation's default is on by default, off by default (recommended) or never; a place may be stricter. Each skill has a switch, with all on and all off (D13).

7The person's skills

Your space's skills follow the person into their own conversations everywhere, delivered by hq by fingerprint. Never in runs others start or scheduled ones. The organisation can turn this off (D15).

8The run

hq names everything by fingerprint, and the site stages it per turn, as now (adr-0084). A clash of the same identity is settled by the order below. Each run records what it used.

When the same skill comes from two places

OrderLevelWhy it wins
1Installed by the organisation (built in, every agent, or this agent)The organisation always uses the same version (D11, D12)
2The project: its files and workspacesA project's procedures and standards prevail (D16)
3The person: their own skillsThey add to the project. To change how the project works, the person writes a skill that complements it, or updates the project's knowledge or memory (D16)

Only the same identity clashes. Different skills all apply. The one set aside is shown on its Skills page as set aside, with the reason.

Before, after, why

Before (board 1)
  • Copies in packages go stale silently (T2).
  • All 18 skills go to every agent (T3).
  • No list of what an agent will see, and no remove (T4, T5).
  • A place's files are live at once, unseen (T6).
  • A repository's skills are ignored.
  • Your skills stay in Your space.
After
  • One installed copy per identity, pinned, with updates offered.
  • Agents get only what they're given; built-ins are the exception.
  • Every level is listed, with switches.
  • Files are off by default until switched on (organisation's choice).
  • Repository skills are read, under the same switches.
  • Your skills follow you.
Compared with the withdrawn version: that draft put every skill into one organisation list. Now only installed skills are one per identity. Skills in files stay where their owners keep them, and the person's travel with the person. Who owns a skill and where it is kept are separate questions (D5).
