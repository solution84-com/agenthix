R1 · Proposals waiting for review

Agents propose and people accept (R6, spec part 5). A proposal is a draft that reaches no agent. It is a new skill, or an edit to an installed one shown as the difference. Each proposal is reviewed at the level it aims at (D27, D28): the organisation's administrators and Library maintainers; a project's administrators; or the person, for Your space. This board covers where proposals surface, the review screen, and what accepting does.

Where a proposal shows up

Before
  • Nowhere. A skill an agent writes is live, unseen (1).
After
  1. The Library: a Waiting for review · 2 filter, and a chip on the skill an edit targets.
  2. The Overview's Needs attention: "2 skill proposals waiting", with Review. It's the reviewer's own notification, so handling the proposal clears it (3).
  3. The proposer's conversation: a card that follows the proposal's state (board C3).
Mechanism: propose_skill creates a proposal record holding the draft's content by fingerprint, the agent, the person, the conversation and, for an edit, the identity it targets. It notifies the reviewers of the level it aims at (D27): for the organisation, administrators and Library maintainers; for a project, its administrators; for the person, only them. The Library filter, the Overview item and the card all read the same record.

Who reviews: by the level a proposal aims at (D27)

Aimed atReviewed byWhereAccepting
The organisation: a new skillAdministrators and Library maintainersThe Library, Waiting for reviewPublishes it as the organisation's own, version 1 (A1 below)
The organisation: an edit to one skillAdministrators and Library maintainersThe Library, and a chip on the skillPublishes the next version, or the organisation's own copy (A2, A3)
A projectThe project's administratorsThe project's Skills page (P1)Publishes it into the project's files/.agents/skills/ as version 1, switched on (FV1)
The personThe person aloneThe card in their conversation (C3)Publishes it into Your space

The person can change the aim on the card before anyone reviews it. Someone who may already publish at the level they aim at gets a draft, not a proposal (D24, U3b): an administrator or Library maintainer for the organisation, a project administrator for a project. Any member may propose; a member's New skill is a proposal unless they may publish at that level.

What accepting does

ProposalAcceptingWho may
A1A new skillInstalls it as the organisation's own, made here (fernhill/release-notes 1), with the proposal as its source. Before saving, the reviewer chooses Add to agents: the proposing agent (preselected, RQ2), every agent, chosen agents, or no agent yetAdministrators (RQ1)
A2An edit to the organisation's own skillSaves the next version, which every agent that has it uses on its next turn (D11). Roll back stays one click awayAdministrators and Library maintainers (D28)
A3An edit to another publisher's skill (for example agenthix/code-review)Makes the organisation's own copy, fernhill/code-review, which takes the original's place, with a basedOn line written once (D18, D19). The review screen says so before savingAdministrators and Library maintainers
A4RejectKeeps the draft and the note under Decided. The conversation's card shows the noteWhoever may accept it
Why: the proposal is the only way an agent's learning reaches a skill that other runs follow. Every path ends in a person's decision, and the result is an ordinary version with history, so nothing about it is special after it is accepted.
