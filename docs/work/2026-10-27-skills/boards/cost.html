10 · Cost: what the model reads per request

Every skill an agent has puts its name and description into every request of every turn. This board is how that stays small, how it's shown, and how it's measured before anything more is built.

Why: a new organisation installs all 18 library skills into its package at first write (orgPackageService.ts), so every agent lists them. On OpenCode the list is written into the system prompt (opencode/openCodeSkills.ts); on Claude, Claude Code lists the plugin's skills itself.

How it's shown (R9, PQ10)

  • Per run: the agent's own levels plus one place's switched-on skills: what a turn there actually lists. The agent's page shows "11 skills · about 1,900 tokens per request" for its usual places (A1).
  • Estimate: the characters of each listed name and description, divided by four, plus the runtime's fixed framing. Labelled an estimate.
  • Warning above about 20 skills or 4,000 tokens for a run: the point where recall drops (Anthropic's enterprise guidance; Claude Code keeps its own listing to about 1% of the context window). It suggests what to take away: skills never used in the last 30 days, from the runs' records.
