1What the run records

When the site stages a turn's skills it keeps a small table for the run: staged name → identity, version, level, and the skill's own fingerprint (one digest over its folder). It reports this with the run, as it reports the run's other facts. It costs a few lines per skill, not content.

2What the step carries

The skill step gains a target: { kind: 'skill', name, identity, level, fingerprint }. It joins task, board and file in WorkTarget. The step's text uses the skill's display name from that table, not the staged name.

3The level in a few words

Built in, the organisation's name (installed), the project's name (its files or a workspace), or Yours (the person's own, D15). The version for installed skills; for a skill in files, its folder.

2 · Clicking it opens the skill beside the thread

Before

Nothing opens. To see what Ada followed, a person would have to find the skill somewhere, and it may have changed since.

The skill opens in the beside panel at the version the run used: its instructions rendered, where it came from, and a way to the Library or the place's Skills page.

Why hq keeps a copy of what was used: skills in files change and hq can't pin them (F1, F2). So the first time a run uses a file skill at a given fingerprint, the site sends its text with the run's report, and hq keeps it, bounded by the same limits as staging. Then "what did the agent follow?" always has an answer, and a skill an agent quietly edited between turns can't hide what it said.
