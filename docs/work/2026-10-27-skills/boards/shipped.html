The rule proposed

KindTestBehaves like
Built in (L1a)Every agent needs it to work in Agenthix, whatever its role. It is about the platform, not a trade.On for every agent; an administrator can switch it off; nobody edits it; it updates with hq. Like Claude Code's bundled skills.
Built into one agentIt is that agent's job, and makes no sense for any other.Ships inside the agent's template (L3), never on the shelf. For Kernel, the platform's own agent, kept up to date by hq.
Offered (L1b)Trade know-how that suits some agents and not others.On the shelf; nothing runs until it's given to an agent, a place or the organisation. Each carries a suited to hint (developer, product, QA, content, research) that the picker uses to suggest it. A hint, not a lock.
FoldedA copy, or a near-copy, of another skill.Removed. Templates name offered skills instead of carrying copies.
"Some skills shouldn't be offered to some agents": the hard case is Kernel's own skills, and those never reach the shelf. For the rest, a hint is enough, since an administrator chooses who gets what. A lock would be a rule nobody needs yet (YAGNI). Q12 asks.

Built in, for every agent

SkillFromWhy built in
working-with-gitThree different guides, in five places, become one: the library's dev-github-operations (139 lines), plus git-workflow in wasp-developer, solo-dev, dev-team and ai-startupAny agent working in a repository must commit locally and push, pull and open pull requests only through approved workflows. That's a platform rule, not a trade. Built in, it can't go stale: an out-of-date copy is exactly what once told agents to push directly. Staged only when the run works in a workspace with a repository, so it costs nothing elsewhere.
skill-creatorSkills-engineer's codify-skill and propose-skill, made generalEvery agent can be asked to "make this a skill". It needs to know the format, a good description, and to propose rather than write a skill live. Claude ships the same thing.
Beside platform knowledge (D6): a built-in tells the agent what to do, step by step. For what things are, it points to the guide's pages (the platform: knowledge level) rather than describing the product again. Task management, knowledge and workflows also reach agents as tools and instructions. The guide's line calling task management an always-on skill is out of date.
