6 · Delivery: hq to site to runtime, per turn

How one turn gets exactly the skills it should, and nothing else. Numbers match the sequence. Staging itself stays as adr-0084 built it; what changes is what hq names and what the site checks before copying.

Today

  • A run's dispatch carries RunPackages: the agent's, the organisation's and the platform's package by digest (core/src/protocol/packages.ts). The site fetches missing ones (packages.missing, packages.put) and caches them.
  • Staging (site/src/agents/runtime/skillStaging.ts) copies five sources (platform, org, agent, boundary, shared) into a fresh folder as <source>-<slug>, rebuilding each header (skillFrontmatter.ts). File sources are copied as they are at that moment, unchecked against anything hq approved.
  • Claude gets a local plugin and a name allowlist (claude/claudeSkills.ts); OpenCode gets a list in the system prompt and Agenthix's skill tool (opencode/openCodeSkills.ts). A typed /name goes through untouched (claude/turnInput.ts).

One turn

The steps

1hq resolves the set

Built-ins not switched off (D6); installed assets every agent has or this agent has, at the pinned version (V1, D23); the place's switched-on file skills; the person's skills at a version they published, only for a turn of their own conversation (D15, H4). Clashes of one identity settle installed, then project, then person (D12, D16); the loser is recorded as set aside.

2The dispatch

Installed and personal content as package refs by digest, as today. File skills as {place, path, fingerprint} triples, never fingerprint alone (H3). An optional skill field when the person picked one with / (R3).

3Fetch missing

packages.missing / packages.put, unchanged. The cache is bounded and outside every container (L4).

4Re-fingerprint and stage

The site reads each named file-skill folder into memory under staging's bounds, fingerprints exactly those bytes, and stages it only if the fingerprint equals the one hq named for that place and path; a mismatch is skipped and reported (H3). Names are unique per run: workspace-<n>-<slug>, person-<slug>; two folders never merge, and a clash stages neither (M2).

5The runtime

Claude: the staged folder as the agenthix plugin with the name allowlist, as now. OpenCode: the list and the skill tool, as now. Headers rebuilt, hooks and inline shell off (adr-0084).

6The picked skill

The site accepts the skill field only if it equals a name staged this turn whose skill allows people to invoke it; otherwise it drops the field and keeps the text. Text starting with / is escaped so the runtime never reads it as a command (M7). Accepted: Claude gets a skill invocation, OpenCode an instruction to load it first.

7Record what was used

The run records each staged skill's name, identity or place + path, version and fingerprint (data board 13), so the work step opens the exact version (R4) and the sweep keeps its content (D26).
