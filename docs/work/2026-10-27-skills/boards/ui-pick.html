A typed /code-review is plain text, which Claude Code may treat as a command and OpenCode won't.

The chosen skill becomes a skill chip at the start of the message. The person writes the rest. Backspace on the chip removes it.

1What hq sends

The message text stays the person's words. Beside it, a structured field: skill: { name: 'org-dev-code-review', identity: 'agenthix/dev-code-review', version: '1.3' }, with the staged name the run will use. hq checks the skill is still in the agent's set before sending; if it isn't, Send says so and keeps the message.

2What the site does

It turns the field into the runtime's own form. Claude: the turn starts with the plugin skill's invocation, then the words. OpenCode: an instruction to load that skill with the skill tool first, then the words. Both arrive at the same place: the model loads the skill's body and follows it.

3In the thread

The person's bubble shows the same chip. Clicking it opens the skill beside the thread (C2), as a file chip opens a file.

Why a field and not text: the person's words are never rewritten, the choice survives the trip unambiguously, and the site, not the text, decides what becomes an invocation (R3).

3 · A typed /word is just words

Before

Typing /update-config and sending reaches Claude Code's bundled command (4).

After

Anything typed is text. If the person ignores the picker and sends /update-config please, the agent receives those words as a request, the same on both runtimes.

  • Mechanism: the site's turn input never passes a message that starts with / to Claude Code as it stands. It is sent so the runtime reads it as words, not a command, for example quoted as the person's message. Only the structured field (2) produces an invocation.
  • Typing a skill's exact name and pressing Enter while the picker is open chooses it, so people who know their skills type /rev ↵ quickly.
  • Closes the known fault: Claude Code's bundled commands can no longer be typed.
