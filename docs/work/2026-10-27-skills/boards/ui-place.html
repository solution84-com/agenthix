P1 · A place's Skills page: switches

A project lists every skill found in its files and its workspaces' repositories, and switches each one on or off (D13, spec part 4). Files stay where skills are kept; hq lists, installs into and switches them. Shown for the project Website rebuild in Fernhill.

Today, numbered

  1. No Skills section. A project's left panel (useProjectPlace.tsx) has Work, Agents at work, Files and Settings, and nothing for skills. A skill exists only as a folder in Files, under files/.agents/skills/.
  2. Everything found is live. Staging reads the place's two folders every turn (skillStaging.ts), so a skill an agent wrote yesterday runs today, for everyone using that agent here (T6).
  3. Repositories are ignored. site-repo's .claude/skills/ never reaches a run (T12).
  4. Nobody can tell what's on. There's no list of what an agent will use here, and nothing records that a skill changed.

Only you see this group. It applies when you talk to an agent here; the project's skills win a clash (D16).
  1. The list: hq asks the place's site to scan files/.agents/skills/, files/.agents/agents/<id>/skills/ and each workspace's three repository folders. The site reports each skill folder's name, description and fingerprint (F1), bounded and with links refused, as staging already reads them.
  2. The switch: hq records on against the fingerprint. Each dispatch names the switched-on fingerprints, and the site stages only those (D13). Switched and published by the project's administrators; anyone with write access edits (D27).
  3. Versions and outside changes (D25, FV1–FV4): each place skill has a version, given when it is published from the editor (U3b), recorded by hq and written into its metadata. A folder written outside the editor, by an agent's file tools, Files or anyone, is in files, not published; a published one changed that way is changed in files, not published, with What changed, Publish as version 5 and Put back version 4. Under off by default it stays off until then. The nav's count draws the project administrators' eye.
  4. Origin: a skill added with Add to this place carries its identity, version and basedOn credit (D19). hq compares it with the installed asset and shows edited here or 1.4 available. Update… offers to overwrite the folder, never automatically (F3).
  5. Set aside: the same identity installed by the organisation wins; the file copy is shown dimmed with the reason (D12).
  6. All on / All off: for the whole page, and for each group. All off on a workspace's group is how a repository's skills are kept out (D13).
  7. New skill and Edit open the editor (U3b) on a draft for this place; publishing writes the folder (FV1). A workspace's repository skills are read-only: their versions are their commits (FV6).
Before
  • Skills hidden in Files.
  • Live the moment they're written.
  • Repository skills ignored.
After
  • One page per place, grouped by where each was found.
  • Off by default until someone looks, where the organisation or the place chooses that.
  • Repository skills listed and switchable.
Why: the switch is the only control hq has over files (F4). Putting it beside each skill, with the reason it's on, off or set aside, answers "what will agents use here?" in one place, and closes the gap where an agent-written skill went live unseen.
