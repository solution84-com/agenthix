HQ's site

One page for the site that carries HQ and the machine under it: The HQ (what people use), The site (its default site) and The machine, once. Shows what only hq-box carries: HQ's version and health, its address, its front door, its backups and its scheduled changes. Spec §6, §11, §12, §14.

What this is

  • The Fleet Console is a site of its own kind that dials out to HQ. By default it runs on HQ's machine (the install starts HQ, its default site and the Fleet Console together), so this is the page a fleet admin lands on most. HQ never runs without its default site, and they upgrade, back up and move together, so they are one page with three groups and the machine appears once. The site's name and the machine's are separate; when the machine connected, the site's name defaulted to the machine's.
  • Agent protections are always on: there is nothing to set and no way to allow a port. Capacity is the only thing that can be changed.
  • Every action here asks hq-box's host service, from a fixed set of actions. The fleet admin role is not given here. It is given in the Fleet Console's Fleet admins tab, or on HQ's machine with agenthix hq fleet-admin <user>; passwords belong to HQ. A backup location is not set here either: the page shows it, and where none is set it shows the command to run on the machine.

Today

No screen. A machine admin reads docker compose ps, backs up with pg_dump and tar, and upgrades with git pull and up -d --build, by hand. hq's own status reports its version as dev.

hq's address and the front door

Setting hq's address, and turning on the host service's own front door — with its warning, defaulting to No, and its refusal. Spec §6, §11, §16.

What this is

  • A front door is the one web server on a machine that holds ports 80 and 443 and the certificates. By default hq listens on 127.0.0.1:4100 and the machine's own web server points at it.
  • On request the host service runs one itself — after a warning that defaults to No, and refused while either port is in use. Its certificate expiry and renewal errors show on HQ's site page (page 1).
  • On a bare network address there is no host for uploaded files: the section reads "No separate host on a bare network address — uploaded files are offered as downloads only, never shown in the page."

Today

No screen. A separate front-door/ stack, started by hand with its warning in the guide; changing HQ_URL means rebuilding hq.

Moving hq

To a new address on the same machine, a new machine or Cloud, with or without its own domain — and what the sites do. Spec §13; diagram 5.

What this is

  • A move is a sealed backup restored on the new machine. With its own domain, hq keeps the address: the domain is pointed at the new machine and sites and host services reconnect as before. Without one — the first screens, where Acme's hq is at http://192.168.1.20:4100 — hq tells each connected site and each host service its new address before it stops; each switches once the new hq passes a challenge–response keyed on the credential it already holds (a host service, on its machine credential).
  • The Fleet Console stays where it runs. It dials hq's new address like a site. When it ran on hq's old machine, as it does by default, it is restored with hq, so fleet admins carry on at 127.0.0.1:4300 on the new machine; one on another machine does not move at all.
  • hq is read-only from the moment the backup starts, with a notice, so nothing is lost between the backup and the switch. Changing hq's address on the same machine is a move too.
  • A site that was offline is pointed at the new address with agenthix site hq-address <address> on its machine, or by the Fleet Console for it. A machine that was offline, or a Fleet Console on another machine, uses agenthix console hq-address <address>.
  • Removing the copy left on the old machine is the move's last step, once the new hq has taken over. It is not an erase.

Today

No screen, and no way to do it: moving hq to a new address strands every site and host service, and each must be unregistered and registered again by hand. Nothing stops people editing while the backup is taken.

Suspend, resume and erase

Stopping hq and keeping everything; erasing it like a recycle bin — a final backup, a 30-day grace period in which restoring brings it back, then a purge. Spec §15; diagram 9.

What this is

  • Suspend stops hq and keeps everything; Resume starts it again. Members see a notice, as for any planned interruption.
  • On hq's machine, agenthix site erase is refused and points to agenthix hq erase: hq's site cannot lose its default site. Erasing any other site is immediate.
  • Erase offers a final export, needs hq's address typed in, takes a final sealed backup, removes the running data, and keeps that backup and its copy in the backup location, if one is set, for a grace period — 30 days by default — when Restore brings it back. Then everything is purged, the copy in the backup location included.
  • At once, or on a date with notice — the person erasing chooses. Nothing forces a wait: the 30 days already undo a mistake. When other people use hq, the screen recommends notice and says how many will lose access without it. With a date, hq shows everyone a countdown.
  • Every erase is announced to all fleet admins and organisation admins. Erasing a site is immediate (its page in hq says it has gone).
