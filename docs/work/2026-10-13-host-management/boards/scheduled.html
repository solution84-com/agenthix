Scheduled

Scheduling an upgrade, resize, restore, move or erase for a set time with notice; changing and cancelling; the maintenance window for automatic fixes. Spec §11, §14; diagrams 6, 6b.

What this is

  • A scheduled change is held by the host service of the machine it affects, which runs it at that time — whoever scheduled it: a fleet admin here, the machine admin with the CLI, or Cloud for its machines (shown here, changed only in Cloud).
  • hq hears of it and tells members; the Fleet Console never sees who the members are, so it says "notice to members" and never lists people.
  • Automatic fixes are on by default, in a window a fleet admin sets.

Today

No screen and nothing scheduled: an upgrade happens whenever someone runs it, and nobody is told.

An upgrade, running and rolled back

An upgrade under way on hq's machine, and one that did not come up healthy and rolled back. Spec §11, §14; diagram 8.

What this is

  • Every scheduled upgrade gives notice, checks that each image is published and signed (an unsigned one is refused, and the page says "0.3.0's images are not signed as published — nothing was changed"), takes a backup first, and rolls back if hq or the site does not come up healthy.
  • A site's upgrade looks the same on its own machine's page.
  • "Report the problem ↗" opens this repository's bug-report form with the version and the failed step filled in — never the logs, which stay on the machine.

Today

No screen: git pull and a rebuild; if it fails, the machine admin restores the dumps by hand.
