The console site

hq stays the hub; the Fleet Console is a special site — the console site — that dials out to hq like every site and is the fleet admins' portal. Every arrow points from the side that opens the connection. Nothing listens on the network except hq's port.

hq, the hubthe console site (Fleet Console portal)host service — acts on its own machinea signed command

1 · After install — everything on the first machine

The install starts hq, its default site and the console site together, each connected to hq by configuration (ADR-0070's pattern). Other machines' sites and host services dial out to hq's port.

2 · The console site elsewhere — optional

It runs wherever the fleet admins want it. Moving hq, or hq moving onto Cloud, does not move it: it only dials hq's new address.

3 · How one command travels — "upgrade office-server"

The shell

The Fleet Console's frame, shown with its Fleet screen: a light menu on the left, with labels, and the page beside it.

What this is

The Fleet Console is a site of its own kind, the console site: it dials out to hq like every site, runs no agents, is not listed in hq's Where work runs, and exposes nothing. It runs on hq's machine by default, and may run on another machine, even a fleet admin's own computer. It shows the organisation's whole fleet: a list of sites, each with the machine it runs on. Organisation admins look after the business's work; fleet admins look after the machines and how they connect (§1). Its frame has five parts:

  1. The top of the menu: the mark and Fleet Console, with a small badge under it for the machine it runs on and the address it listens on: on hq-box · 127.0.0.1. There is no bar across the top.
  2. The menu on the left, in this order: Fleet, Scheduled, Backups, Activity, Fleet admins, Remote access. Fleet is the home screen. It is shown with labels on every page, the current item in a soft slate highlight. Collapse, at its foot, folds it to icons only for anyone who wants the room. Activity lists what every fleet admin did and what the command line did (shown as machine admin), kept for a year.
  3. The signed-in fleet admin, at the foot of the menu, with their initials and their role named: a fleet admin is an hq account that holds that role, and signs in with its hq login. The name opens a menu with Your account and Sign out. Every action is recorded against this person (§7).
  4. Local only: a footer on every screen says the page is served to this machine alone and whether remote access is on. When remote access is on, the Remote access screen replaces this footer with the session notice and the time left.
  5. Type: one typeface throughout. Machine and site names are semibold text (hq-box); the code font is kept for what is typed or copied: commands, paths, addresses and codes.

The Fleet content is the landing design on the next page: the hq hero card, then overview tiles, then a score card per other site.

Opening the Fleet Console

Crossing C1 (§4, §7, diagram 1): the Fleet Console is a site of its own kind and listens on 127.0.0.1 of its own machine only — by default hq's machine. There are three ways in, and all three end in the same sign-in: your hq login.

What this is

The Fleet Console has no address on the network. A browser on its own machine reaches it at http://127.0.0.1:4300; anyone else reaches it by making their own computer look like that machine — an SSH tunnel — or, while someone at that machine has it on, through the remote-access tunnel (page 4). Being able to reach it is not enough: 127.0.0.1 is open to every user and program on the machine, so a sign-in is always needed (page 3). It is your hq login (username and password), checked by hq, and only an account with the fleet admin role gets in. On the machine or over SSH the hq login is enough; through remote access it also needs a six-digit code from an authenticator app. The Fleet Console has no accounts of its own.

Which machine. Hq's machine, hq-box, unless it was moved: it may run on another machine, even a fleet admin's own computer, and it does not move when hq moves. Wherever it runs, the menu's top reads Fleet Console, with on that machine beneath it. Every page here uses hq-box.

Today

Nothing: there is no Fleet Console. Machine work is docker compose on the machine itself.

The three ways in

1 · On the Fleet Console's machineOpen a browser on hq-box itself and go to http://127.0.0.1:4300. agenthix status prints the address.
2 · Through an SSH tunnelFrom your own computer, with an SSH login to hq-box:
ssh -N -L 4300:127.0.0.1:4300 sam@hq-box
then open http://127.0.0.1:4300 on your computer. Close the command to close the tunnel.
3 · Through remote accessOnly while someone has turned it on at hq-box: open the address it shows, under Cloud's domain, such as https://hm-x7f3k2.relay.example.example. Sign-in needs your hq login and an authenticator code. Every session is announced. See page 4.

On hq's own address (hq.acme.example) there is no path to the Fleet Console either; hq never links to it as a page.

Where it runs: on hq's machine, or moved

The install starts hq, its default site and the Fleet Console together on one machine. To run the Fleet Console somewhere else, a machine admin of hq's machine makes a one-time code, and the command on the other machine brings it up there; the old one is retired. Nothing about the screens changes except the machine named under the name at the top of the menu.

sam@hq-box — terminal
$ agenthix hq console-code
A one-time code for a Fleet Console on another machine (works once, for 1 hour):

  Hm4q-7tZw-3Lp9

On that machine, run:  agenthix console install https://hq.acme.example Hm4q-7tZw-3Lp9
The Fleet Console now on hq-box is retired when the new one connects.
sam@laptop — terminal
$ agenthix console install https://hq.acme.example Hm4q-7tZw-3Lp9
Fleet Console connected to HQ. It runs on laptop and answers on 127.0.0.1:4300 there.
The Fleet Console on hq-box has been retired.

In the user guide

Open the Fleet Console

The Fleet Console is where fleet admins look after the machines that run Acme Robotics' hq and sites. For safety it is not on the network at all: it answers only on its own machine — hq's machine unless it was moved — at http://127.0.0.1:4300. Visiting the machine's address from anywhere else shows your browser's “can't connect” page — that is expected, not a fault.

On its machine

Open http://127.0.0.1:4300 in a browser there.

From another computer, over SSH

If you can log in to the Fleet Console's machine with SSH, run this on your own computer and leave it running:

ssh -N -L 4300:127.0.0.1:4300 you@the-fleet-console-machine

Then open http://127.0.0.1:4300 on your computer. The tunnel closes when you stop the command.

From anywhere, for a while

Someone at the Fleet Console's machine can turn on remote access for a set time (Remote access, below). Without Cloud, the same can be done with your own tunnel to 127.0.0.1:4300 on that machine.

Then sign in

Sign in with your hq account (username and password). You need the fleet admin role; a fleet admin can give it to you in the Fleet Console. On the machine or over SSH that is all. Through remote access you also need the six-digit code from your authenticator app.

Your account

The signed-in fleet admin's own page: who they are in hq, how they sign in here, their own Cloud sign-in, and signing out.

What this is

  • Opened from the person at the foot of the menu: Sam Rivera ▾ → Your account. No menu item is selected while it is open; the person at the foot is.
  • The Fleet Console has no accounts of its own. Fleet admin is a role on an hq account, and sign-in is the person's hq login, checked by hq. Password and name belong to hq: the page links to hq for them (Change in hq ↗) and does not change them here.
  • The authenticator code is the one thing kept here besides the person's own Cloud sign-in. It is asked for, with six digits, only through remote access; on the Fleet Console's machine or through an SSH tunnel the hq login is enough. It is set up on the Fleet Console's machine, with ten recovery codes shown once, and reset there with agenthix console reset-code <user>. Recovery codes left are counted.
  • Agenthix Cloud: Sign out of Cloud ends this person's Cloud sign-in, so Cloud's sites leave their fleet until they sign in again; the link stays. Forget removes the person's linked Cloud account, whose identifier is the only thing kept (C6). The organisation's connection to Cloud, which remote access uses, is separate: it is on hq's site page and changed only on the Fleet Console's machine. With none linked: Link a Cloud account ↗.
  • Sign out of the Fleet Console sits at the foot of the page, as well as in the menu.
