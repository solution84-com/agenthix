Fleet — overview and site cards

The Fleet Console's landing screen: hq first, as a hero card, then six figures for the whole fleet, then each other site as a score card.

What this is

  • hq is the hero, at the very top. A full-width card titled Acme Robotics' hq, above the tiles, because hq is the thing the whole fleet serves. It says where hq runs at a glance: a light card with a slate edge, a Self-hosted badge and on hq-box, or, when Cloud runs hq, Cloud's sunrise mark and Agenthix Cloud · hel-1 (drawn below). It carries hq's address, its health in a sentence, its version and the fix scheduled, the last backup and the backup location, Connected to Agenthix Cloud as Acme Robotics when it is, and its default site's runs. Actions: Open hq ↗, Back up now, Upgrade…, Move hq…. Clicking the card opens hq's site page (page 3). The hero is hq's site: it is not shown again as a card below.
  • Then the overview. Six tiles answer "is everything all right?" before any card: sites, needs attention, agents running against capacity, the next scheduled change, the last backup (the latest nightly backup and, if a backup location is set, that it reached it), remote access.
  • Every machine carries one site, and the two have their own names: the site's name starts as the machine's, and from then on they are stored apart (a site that moves keeps its name). (2026-10-16: superseded by ADR-0120 — a site is always named after its machine, and a move or a restore renames it after the new one.) There is no machine that only stores backups. The tiles count hq's site with the others.
  • Then a score card per site — the site's own name, then Self-hosted · on <machine> (or Cloud · on Cloud's machine), always written, even when the two names are the same — with meters for agents against capacity, disk and memory, its version and its next scheduled change. Each meter writes its figure; the bar only repeats it. A site that needs attention comes first in its group, full width, with its one action.
  • Groups: Agenthix Cloud first, under its pill and count, then Self-hosted sites. Who is signed in to Cloud, and signing out, moved to Your account (the last page of this part). The group has four states, drawn below the fleet: not connected, connected with no Cloud sites yet, connected with sites (the mock above), and hq itself on Cloud. A fleet admin who has not signed in to Cloud sees one line instead of the sites (page 8).
  • The organisation's connection to Cloud is shown on hq's site: a small Agenthix Cloud mark and Connected as Acme Robotics. It is made and removed on hq's site page (page 10), only on hq's machine.
  • hq's site is the hero, not a card. The groups below are the Agenthix Cloud sites, then the Self-hosted sites, each in its own card. If Cloud runs hq, the hero says so and the Cloud machine hq runs on is not repeated in the Cloud group.
  • Only the machine side shows: health, disk, versions, capacity, scheduled changes, backups, and how many agents run — never the organisation's people, projects or work.
