Remote access

§7 (remote access), crossing C1, diagram 2: a tunnel turned on for a while, only at the Fleet Console's machine. Off unless turned on; ends by itself; every session announced.

What this is

  • Who can turn it on or extend it: only someone at the Fleet Console's machine — the Turn on button on the Fleet Console's screen opened on hq-box or through an SSH tunnel, or agenthix console remote on. A session that came in through remote access sees the state, the time left, who is connected and Turn off — never Turn on or Extend; it is told to go back to the machine. Cloud can never turn it on.
  • How long: 2 hours by default, at most 8. It needs Acme Robotics connected to Agenthix Cloud, since the relay is Cloud's. This tab holds no Cloud link. The connection is the organisation's, held by the Fleet Console: shown on hq's site card, made and removed only on the Fleet Console's machine from hq's site page (agenthix cloud connect / disconnect; see the fleet pages), and separate from any fleet admin's own Cloud sign-in (page 5). When it is not connected, this tab says so in one line, with a way to that page, and Turn on is unavailable.
  • Signing in through it needs your hq login plus an authenticator code, set up on that machine (page 3).
  • Who can turn it off: anyone — a fleet admin locally or remotely, or the machine admin at the command line — at any time.
  • The honest note: Cloud cannot read the traffic, since encryption ends at the Fleet Console, but Cloud controls the relay's domain and so could in principle get a certificate for it. The screen says so when it is turned on, and the guide says so.

While it is on, the Fleet Console dials out to Cloud's relay and is reachable at an address under Cloud's domain. Your connection stays encrypted all the way to the Fleet Console; Cloud passes on what it cannot read. Every session is announced to every fleet admin and organisation admin, and it switches itself off when the time is up.
