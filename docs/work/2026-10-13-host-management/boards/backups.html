Backups — the journeys

The seven things that happen to a backup, in order, from the nightly run to undoing an erase. Spec §12, §15; diagrams 4, 7.

What this is

  • One line per journey, left to right. Each step is a screen or a command already drawn on the pages before this one.
  • Throughout: every backup is sealed; a machine's own nightly key is held by its host service; a backup location's or an export's key is held by the person who made it. After any restore, hq and the sites reconcile and hq says plainly what was lost.

The backup location: shown here, set on the machine

Per site: a folder the machine can write to, sealed with a key shown once (§12). The Fleet Console shows it; it is set and changed only on the machine itself.

What this is

  • Every site backs up nightly at the fleet's backup time (02:00), sealed, on its own machine. A backup location adds a copy in a folder the machine can write to — a network address, a NAS, a synced drive, a mounted bucket. Not set until someone chooses one. Agenthix Cloud is not a backup location for a self-hosted organisation.
  • It is set only on the machine itself, with agenthix backup location <path> (§12). The command tests a write, then shows the key once. There is no Choose a folder… button in the Fleet Console, so neither a takeover of hq nor a stolen session can send copies elsewhere.
  • The site's Backup location section shows the folder, the last copy and who set it. Where none is set, it shows the command to run on that machine. This is the same on the Fleet Console's machine, through an SSH tunnel and through remote access.
  • Setting or changing it is announced to every fleet admin and recorded in Activity as the machine admin who ran it.
  • Without one, a site has its nightly backups and exports; its page says when the last export is old (page 3).

Backups

Every site backs up nightly, each machine on its own; a backup location is a folder, set on the machine itself; restoring a night. Spec §12; diagram 4.

What this is

  • Every site backs up at the fleet's backup time (02:00), sealed, labelled by night: its database and workspaces; hq's site also holds hq. Sealed means encrypted so only the holder of its key can read it. There is no backup across machines.
  • A backup location is a folder the machine can write to (a network address, a NAS, a synced drive, a mounted bucket), chosen per machine. It is not set until someone chooses one. Agenthix Cloud is not a backup location for a self-hosted organisation.
  • Setting one happens only on the machine itself: agenthix backup location <path> takes a path as that machine sees it, runs a test write, and shows a key once. The Fleet Console shows the location and, where none is set, the command to run there; it has no Choose a folder… button, so a stolen session or a takeover of hq cannot send copies elsewhere.
  • Restoring a night on the same machine is this page; a lost site is Add a site › Restore from a backup; hq's lost machine is agenthix restore --from (see Backups — the journeys).

Today

No screen and no schedule: the deployment guide's pg_dump and tar commands, unsealed, run by hand before an upgrade.

Exporting a backup

A backup a person carries away, with a key made for it. Spec §12; diagram 4.

What this is

  • An export is of one site, and is the way to keep a copy when no backup location is set. It takes a night's backup (or a fresh one), seals it with a key made for that export only, and hands both over: the key shown once on screen, or saved as a small file.
  • Every export is announced to all fleet admins and organisation admins (§4).
  • Bringing one back is Add a site › Restore from a backup (choose the export file, enter the key) or, for hq's machine, agenthix restore --from <file> on a new machine.
  • A site's page says when its last export is old, if it has no backup location.

Today

No screen. The hand-made dumps are not sealed at all.
