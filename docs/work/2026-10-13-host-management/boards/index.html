What these boards cover

The screens of host management, designed here and kept as the build's baseline. The design spec (spec.md, beside these boards) holds the rules; these boards show what people see and do. Each screen is drawn once, with a Light/Dark switch.

How to read them

  • Start with The redesign and Plan maintenance. After reviewing the built Fleet Console on 2026-10-16, the owner agreed a redesign: a Dashboard, HQ's own page, a page per site named after its machine, the menu in three parts, notices beside the menu, Activity as the record, Maintenance in one panel, and Help. The earlier boards they replace stay, each marked superseded at its top and in the menu.
  • The menu groups the earlier boards by feature, in the order of the Fleet Console's first menu: Fleet, Sites, HQ's site, Scheduled, Backups, Activity, Fleet admins, Remote access; then HQ's own screens and the command line.
  • Each page says what the screen is, how it was before where one existed, and then the screens themselves.
  • The look and Defaults in the design hold the decisions every screen follows.

Decided

#Decision
U1One design language for HQ, the Fleet Console and Agenthix Cloud, each with its own colour — HQ indigo, the Fleet Console slate, Cloud blue — in light and dark; see The look.
U2The Fleet Console is a plain Node server serving a React app, like the site (ADR-0086) — not Wasp, which brings sign-in and data layers it would not use.
U3Every site carries a badge for where it runs — Self-hosted or Agenthix Cloud — the same in HQ, the Fleet Console and Cloud.
U4The guide's words: machine admin, fleet admin, organisation admin; HQ in capitals on screen; states in sentences; never colour alone for state; each change its own action, named for what it does, and scheduled change as the one general word. (2026-10-16: the last two superseded by Plan maintenance — the general word is maintenance, and every kind is planned in one panel.)
U5These boards are the UI's design record, committed beside the spec as the build's baseline; there is no separate UI spec.

The look

Decided: one design system for three portals, each with its own identity and frame — hq indigo with its sidebar, the Fleet Console slate, in Cloud's layout: a light sidebar with labels and a soft glow behind the title, Cloud sunrise with its banner. Every colour below is a token — the same token names in all three portals, different values. State colours are shared, so Healthy, near capacity and Not reachable look the same everywhere.

Defaults in the design

Smaller calls, settled as defaults and drawn that way on every board.

Fleet and sites

#Default
F1Sites are ordered: needing attention first, then by name. hq's site leads its group. (2026-10-16: superseded by The redesign, 7 — a steady order, HQ's site first and then by name; a problem shows by its dot.)
F2A site and its machine have their own names. When a machine connects, the site's name defaults to the machine's; a site that moves keeps its name. Cards and pages read "office-server · on new-server". (2026-10-16: superseded by ADR-0120 and The redesign, 1 — a site is always named after its machine, and a move or restore renames it.)
F3A Docker Desktop machine that stops answering reads Asleep; a server reads Not answering and needs attention. (2026-10-15: superseded by the setting Notify the fleet admins if this machine stops answering (spec §10) — ticked, a silent machine reads Not answering and needs attention; unticked, Not heard from; stopped on purpose, Stopped on its machine.)
F4Disk needs attention at 85% full; at 95% it says new runs may fail.
F5Actions on Cloud's sites go through Cloud's API; when Cloud refuses, its own reason is shown word for word.
F6Cloud's sites are shown only after signing in to Cloud.
F7hq-box offers no Disconnect; site erase on hq's machine is refused and points to hq erase.

Agenthix Cloud

#Default
C1Connecting the organisation needs its owner or a fleet admin of it on Agenthix Cloud, signing in on the Fleet Console's machine.
C2Disconnecting warns first and lists the sites Cloud runs, which stop taking part; remote access switches off.
C3Connecting and disconnecting are announced to every fleet admin and organisation admin.
C4Moving hq onto Cloud uses the fleet admin's own Cloud sign-in.

Backups

#Default
B1A restore checks the key before it changes anything, and backs up the current state first.
B2A lost site is restored from the Fleet Console (Add a site › Restore from a backup) or on the machine with agenthix site restore --from <location or file>.
B3The backup location is set per machine, on that machine — there is no "same on every site" shortcut.
B4The erase screen's "12 people use this hq" is a count hq gives the Fleet Console, never names.
B5No early purge; "Purge now" does not exist.

Fleet admins and remote access

#Default
A1Remote access runs for 1, 2, 4 or 8 hours, 2 by default; running agenthix console remote on again extends it, on the Fleet Console's machine.
A2remote on refuses, with the fix, when the organisation isn't connected to Cloud or no fleet admin has an authenticator code.
A3Turning remote access on is announced, as well as each session; a recovery code used through it is announced too.
A4Granting or removing the fleet admin role is announced to every fleet admin and organisation admin; the last fleet admin cannot be removed in the Fleet Console.
A5A connected organisation's fleet admins on Cloud are listed under Fleet admins; one becomes a fleet admin here only when a fleet admin here gives the role (Give them the role here too) or a machine admin of hq-box does.

hq and members

#Default
H1hq never shows commands or links to the Fleet Console to members: "Your fleet admins can see why."
H2hq's state words for a site: Available, Busy, Unavailable, plus a planned interruption.
H3A move pauses runs first, as every scheduled change does; hq shows no time estimate — "until the move finishes".
H4hq never lists host services; the Fleet Console shows which machines followed a move.

The command line

#Default
L1One command to leave: site erase (30-day recycle bin); site remove and site join do not exist.
L2capacity, front-door and scheduled are on the machine; removing the old copy after a move has no command — it is the move's last step.
L3agenthix install asks one question and prints one link.
