Installing Agenthix on a machine

Spec §6 and §17. One documented docker run starts the host service; agenthix install inside it asks one question (never the state folder), pulls signed images, starts hq, its built-in site and the Fleet Console, prints the command that saves the shortcut for the person to run, and prints one link for the first account, which holds both the organisation admin and fleet admin roles.

What this is

  • The first thing a machine admin types. No clone of the repository; only Docker.
  • The host service runs as a container named host; the CLI ships inside it, so the first install is typed as docker exec -it host agenthix install. The shortcut command it prints turns that into agenthix …; install never writes it itself.
  • hq listens on its local port; the CLI says how to put the machine's own web server in front of it, or how to let Agenthix do that (agenthix front-door on, page 6).

Today

A clone of the repository and ./agenthix install, which builds every image from source and writes two settings files into the clone (cli/lib/install.sh).

How to read the terminals: bold is what the person types; an underlined value is their answer to a question. Colour is used only on the first word of a state (Running, Waiting, Stopped) — that word says the same thing without it.

agenthix status — the hq and the site on a machine

Spec §9. One site per machine, and on hq's machine hq as well, each in one block: where it runs, its version, and its state as a sentence that ends in what to do next. The site has the machine's name. Never an internal word.

What this is

  • One command for the whole machine, whatever runs on it: hq, its site, the Fleet Console, the front door. Every machine runs exactly one site, and hq is an add-on that hq's site carries, so there is never a name to type.
  • The site takes its machine's name: office-server, not a second name. On hq's machine it is the site that comes with hq.
  • hq never stands alone: on hq's machine the site always carries hq and its default site, and is badged hq · site. No machine exists only to store backups.
  • Each site backs up on its own every night at 02:00, sealed. Status says when the last backup was made and whether a copy reached the backup location; with none set, it says so and how old the last export is.
  • A controller (the Fleet Console or Cloud's controller) may read the same status; it is the only machine command they may ask of hq.

Today

Two commands that print internal words. hq's ./agenthix status prints the default site's state field (hqMachineCommands.ts); a site's agenthix-site status prints the link's status field and the bare error (agenthix-site.mjs). A site revoked while it was off shows DEGRADED and a 401 for ever.

How to read the terminals: bold is what the person types; an underlined value is their answer to a question. Colour is used only on the first word of a state (Running, Waiting, Stopped) — that word says the same thing without it.

The machine's way into hq

Spec §9. Four commands that only someone on hq's machine can run: one link for the first account (or an admin invitation when every admin has gone), a one-time link to set a person's password, the fleet admin role given to an account, and a one-time code to move the Fleet Console to another machine. They run in hq through its private control socket; a controller is never offered them.

What this is

  • The root of trust for hq: whoever can use Docker on hq's machine can always get back in.
  • Every use is told to the organisation admins, so it is never silent.
  • On a machine with no hq, the commands say where hq runs instead of failing obscurely.
  • The first account holds both roles, so there is one link, not two. Fleet admin is a role on an hq account: the person signs in to the Fleet Console with their hq login.

The Fleet Console from the command line

Spec §6 (connecting a machine), §7 and §13. Running the Fleet Console on another machine, the authenticator code, adding a site by a code and a fingerprint both sides compare, leaving, the address to use after hq moved, the Fleet Console's own link to Cloud, and remote access for a time.

What this is

  • The Fleet Console is a site of its own kind: it dials out to hq like every site, runs no agents, and shows its screen at 127.0.0.1 of its own machine only. It runs on hq's machine by default and does not move when hq moves; agenthix hq console-code and agenthix console install run it elsewhere.
  • It has no accounts of its own. A fleet admin is a role on an hq account, and people sign in with their hq login. The first account, made by the install link, holds the role; agenthix hq fleet-admin (page 3) gives it to others.
  • Adding a site needs both sides: a one-time code from a fleet admin (Add a site in the Fleet Console), then the machine admin's command, then the fleet admin confirms the name and fingerprint they see. The site then starts and takes part in hq at once. No organisation admin approves it.
  • Remote access is a tunnel through Cloud's relay that is turned on, or extended, only at the Fleet Console's machine — here, or on the Fleet Console's screen opened on that machine or through an SSH tunnel. Anyone can turn it off. Every session is announced. It needs Acme Robotics connected to Agenthix Cloud and at least one fleet admin with an authenticator code.
  • The organisation's connection to Agenthix Cloud, held by the Fleet Console, is made and removed only at the Fleet Console's machine: cloud connect and cloud disconnect. It is not a fleet admin's own Cloud sign-in, which they keep under Your account.
  • On the machine or over SSH a fleet admin signs in with their hq login. Through remote access they also need an authenticator code from an app; it is set up on the Fleet Console's machine, and a lost phone only stops remote sign-in. agenthix console reset-code <user> resets it there.
  • None of these commands exists today: machines are not connected to anything but hq.

How to read the terminals: bold is what the person types; an underlined value is their answer to a question. Colour is used only on the first word of a state (Running, Waiting, Stopped) — that word says the same thing without it.

The site on a machine

Spec §6, §8, §10 and §13. One site per machine, named after it, added from the Fleet Console. What is left on the machine: pointing it at hq's new address, and what each agent may use.

What this is

  • A machine has at most one site, and it has the machine's name (office-server). agenthix status shows it; there is no name to type in any command.
  • There is no site add, site join or site remove. A site is added in the Fleet Console (Add a site): agenthix console connect with the code starts it, and it takes part in hq at once. Leaving is agenthix site erase, which keeps everything for 30 days (next page).
  • A site that was offline during a move is pointed at hq's new address with agenthix site hq-address. The check is a mutual challenge–response: the new hq proves it holds the record of this site's credential, the site proves it knows the credential, and the credential never crosses the network.
  • capacity is the machine's, not hq's: what each agent container may use. hq or a project may narrow it for a run, never raise it. Protections have no setting.

Warnings that ask before acting

Spec §6 (the front door) and §15 (erase). Each says what it will do and what it cannot undo, then asks; the front door defaults to no and a script needs an explicit flag, and an erase needs the name typed. Nothing has happened when it stops.

What this is

  • agenthix front-door on: the host service runs its own web front door, holding hq's certificates. It takes ports 80 and 443, so nothing else on the machine can serve web traffic on them. Refused while either port is in use.
  • Erase: a final sealed backup, the running data removed, and that backup and its copy in the backup location kept for a 30-day grace period during which a restore brings hq back; then everything is purged. agenthix hq erase erases at once; --on <date> schedules it, and hq shows everyone a countdown. Confirming needs hq's address typed in; the site's name (the machine's) for a site.
  • agenthix site erase is the only way to remove a site from a machine. It stops taking part in hq and removes the running data, and keeps a final backup 30 days like any erase; site restore brings it back
  • Today a front door is started by hand from the repository's optional Caddy setup (front-door/compose.yml), with no check that ports 80 and 443 are free; nothing erases an install.

How to read the terminals: bold is what the person types; an underlined value is their answer to a question. Colour is used only on the first word of a state (Running, Waiting, Stopped) — that word says the same thing without it.

Backups: the backup location and restoring

Spec §12. Every site backs up nightly on its own; a backup location is a folder the machine can write to, chosen at the machine. Restoring hq's lost machine is one command on a new machine.

What this is

  • agenthix backup location <path>: choose the folder, as this machine sees it (a network address, a NAS, a synced drive, a mounted bucket). The machine tests a write, shows the key once (or saves it as a file), and the person confirms they stored it. Every fleet admin is told. It is set only here, on the machine: the Fleet Console shows it, and where none is set it shows this command to run on the machine — it has no Choose a folder… button. Agenthix Cloud is not a backup location for a self-hosted organisation.
  • agenthix restore --from <folder or file>: on hq's new machine after the old one is lost. It brings back hq, its default site and the Fleet Console, from a backup location or an export file, with the key. A lost site on another machine is restored from the Fleet Console (Add a site › Restore from a backup), not here. Restoring the same machine, one night back, is also the Fleet Console's (the site's page › Backups › Restore).
  • After any restore, hq and the sites reconcile and hq says plainly what was lost.
