Proposed: one viewer, one rule

  1. A file you click where it's mentioned (a chat chip, a task's attachment or description, a README, a message, a run's output) opens in the file viewer over the main area: the whole page between the menu and the chat. The page you were on stays underneath, untouched.
  2. The chat stays where it is, beside the file, so you can talk to the agent about what you're looking at. If the chat was expanded or over the page, it goes back to its docked width while the file is open.
  3. Full screen is one click away, in the viewer's header, for a wide table or a PDF: it covers the menu and the chat too. ✕ and Escape bring you back to the viewer.
  4. Every viewer has the same header: ‹ back to where you were (named: "‹ QR-1", "‹ Conversation"), the file's name and folder, Download, Full screen, ⋯ (Copy link, Show in Files, Mention).
  5. The Files tool is the file's home, for browsing. Opening a file there folds the tree away (D1), so it looks and behaves like the viewer, with "‹ data" back to the folder.
  6. The address holds the open file, so the browser's Back closes the viewer, and a copied link reopens the same file in the same viewer.
  7. On a phone the viewer is the whole screen, with the same header. This is what the phone almost does already.

What stays: a workspace's git changes keep their diff view (comparing is a different job). "Shown" items an agent puts beside a voice conversation keep their place in the chat; only files move.

The one question for you: the viewer over the main area, with the chat staying beside it (recommended: you can ask the agent about what you see, like ChatGPT's canvas), or over the whole window, hiding the chat until you close it? Full screen covers the whole window either way.
