7 · Steps and progress

A workflow is a list of named steps, as in a GitHub Actions job, so a person can follow a run step by step and see at once where it stopped. Each step names the secrets it needs, and gets only those.

How steps are written

New · nothing today

The agent writes one definition file in the GitHub Actions style, which models already know well, plus any script files the steps call. Everything in it is part of the version that's reviewed and approved.

name: deploy-staging
description: Build, upload and restart the app on staging
hosts: ["registry.npmjs.org:443", "staging.example.com:22"]
variables: [STAGING_HOST, NODE_ENV]   # every step has these as $STAGING_HOST, $NODE_ENV
timeout: 10m
steps:
  - name: Build
    run: npm ci && npm run build       # no secrets: installs from the lock file
  - name: Upload
    secrets: [STAGING_DEPLOY_KEY]
    run: ./deploy/upload.sh            # rsync dist/ over ssh
  - name: Migrate the database
    secrets: [STAGING_DEPLOY_KEY]
    run: ./deploy/migrate.sh
  - name: Restart the app
    secrets: [STAGING_DEPLOY_KEY]
    run: ./deploy/restart.sh
  - name: Check it answers
    run: curl -fsS "https://$STAGING_HOST/health"
  • Each step has a name, which is what people see, and run, a command or one of the version's files.
  • Each step lists the secrets it uses, and receives only those; a step that lists none receives none. The workflow lists the variables it uses once, at the top, and every step has them as environment variables ($STAGING_HOST). Both lists are how "Used by" is known.
  • Steps run in order, each in its own container, sharing the workspace, so what one step builds the next can use (board 6).
  • The first step that fails stops the run; the steps after it are marked skipped.
  • A step may have its own timeout; the whole run also has one.

How progress gets there

  1. The site starts each executor container in turn, and removes it when the step ends.
  2. As each step starts and ends, the site sends a step event (name, state, time, masked output so far) to hq over the control channel, the way a run's status reaches hq today.
  3. hq updates the run's page and its card in the conversation as the events arrive.
