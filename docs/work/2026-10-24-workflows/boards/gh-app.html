  1. The App's permissions are a ceiling. Registering from Agenthix starts with Agenthix's list; an owner changes it on GitHub, where all of GitHub's permissions are. hq reads the real list and shows it here, and shows which GitHub accounts have accepted the latest change.
  2. A "GitHub account" is a GitHub organisation, or a person's GitHub account, where the App is installed. An owner of that account installs it on GitHub; Agenthix doesn't. You can have several: live work, tests, an archive, or an agency's clients.
  3. Which projects can connect to each account: every project (your own organisations), or chosen ones (a client's), so one client's projects never reach another's repositories. A person's own storage is a place of its own here: none can connect unless an admin chooses them, so a member can't link a client's repository into their own storage and approve workflows on it. hq checks this rule each time it mints a token, not only when a workspace connects (board 9, the mint gate).
  4. A project has a default account in its own GitHub section; each workspace starts with it and can choose another the project may connect to. A run's token is for its workspace's repository only.
  5. A new account must be allowed first. Anyone can install the App on their own GitHub account, so a new one shows as "wants to connect" and isn't used until an admin allows it.
  6. One page, GitHub, in the admin portal's left panel (Manage organisation › Settings › GitHub), with the other settings. It already has that entry; registering the App moves onto it from Infrastructure, whose GitHub App card becomes a link here.
  7. No Refresh button. After GitHub sends the person back, hq asks GitHub again every few seconds for up to a minute until the new installation appears, and says "Waiting for GitHub…" meanwhile.
  8. Each installation says what it can reach (all repositories, or how many selected) and so what it can do: create, or link only.
  9. The App's permissions are listed with what uses each, and the line that each run gets only what it declares.

How a client connects

After · proposed
  1. You send an install link from this page, with the note.
  2. An owner of the client's GitHub organisation opens it, on GitHub. GitHub shows your App and what it may do, and asks which repositories to allow: all, or chosen ones. They need no Agenthix account, and you never need their password.
  3. Your Agenthix shows "north-ltd wants to connect". You allow it and choose the projects that use it.
  4. Your agents work on their code through your workflows, with tokens that reach only the repositories the client allowed, and only from those projects.
The client stays in control. They can change which repositories you reach, or remove the App, at any time in their own GitHub settings, and your access stops at once.

Why

  • "Selected only" is what made Back up fail (P1). Saying it here, before anyone connects a repository, is the first half of the fix; G2 is the second.
  • A first set-up is one page top to bottom, instead of two areas and a button that has to be pressed at the right moment.
