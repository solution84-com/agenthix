  1. The switch and Run are in the screen's header, for administrators; anyone in the project can press Run while it's on.
  2. Steps is the approved version as people read it: each step's name, what it runs (files one click away), and which secrets that step gets. A step with none, like Build, is shown as such.
  3. Versions lists every version: proposed by, reviewer's risk level, approved or declined by and when; any two can be compared.
  4. Runs is this workflow's history; each opens the run (U5).

Why

  • Steps first, because "what will this do if I press Run?" is the first question.
  • Each secret flagged with 🔒 on the step that gets it, so what can touch a secret is never more than a glance away.
