Design pass · 8 · The skills screens · settled 5 November 2026

Settled design

Overview: what changes

future state

Making a skill works, and the editor stays as it is. What changes is everything around it: a skill reaches agents in the step that brings it in, a place's Skills page starts with its skills, a skill's versions work like a workspace's, and a member is never handed a form they cannot finish.

The four critical problems, and the answer to each

  1. A member fills in New skill, then is refused → a member does not see the Library's New skill; the Library says where they can make one, Your space (What a member sees).
  2. Installing or publishing gives no agent the skill → both end on Which agents use it?, and who uses it is the first thing in a skill's header (Bringing a skill in, A skill's page).
  3. Hard to tell which skills are on in a place → the list comes first, each row says its state in words, one action per row; the setting for skills found in files is one folded line (A place's skills).
  4. Rolling back is hard to find, under four names → the version is in the skill's header, as main's version is in the workspace view; choosing an older one shows it, with Return to this version…. One name everywhere (Versions).
Not changing what the product does. Every screen uses what exists today: who may make an organisation skill, choosing agents, versions and rolling back, switching a place's skills on and off. Only where and how they are shown changes.

What changes

  1. One button, ＋ Add ▾, holds New skill (make one) and the three ways to bring one in. The separate New skill and Add skill buttons, and the third way in from the Add page, go.
  2. Each row shows its description, and one line of state in words: who made it, its version, and how many agents use it. A skill that needs something from the person says what (Draft not published yet).
  3. Six state filters become one, Needs you, shown only when something does: drafts, updates waiting, items no agent has. The type chips stay.
  4. One name per skill: the name it was given, with its identity (agenthix/skill-creator) on its page, not a second name in lists.

What changes

  1. Publishing and installing both end on Which agents use it?: Every agent, Chosen agents, or Not yet. The choice is the same one as on the skill's page, made where the person already is.

What changes

  1. The files are the page. The skill's folder tree on the left, one file open whole on the right, filling the window; a long file scrolls in its own pane. SKILL.md opens first, read as a page, its name and description a small table above it; Source shows the file as written. Download takes the whole skill; where it cannot, it says why.
  2. Who uses it is a button in the header, the first thing after the name: Used by 2 agents ▾, or No agent uses it ▾ standing out until one does. It opens the list, with ＋ Add an agent and Every agent instead. A change still takes effect on each agent's next turn.
  3. About is a button, as in the workspace view: where it came from, who made it, its identity, who can edit, its signature and credit.
  4. The version is the last part of the breadcrumb (1.1.0 · in use ▾). Choosing an older one shows it, read-only, with Return to this version… and Back to the version in use. One name, Return to this version, replaces Roll back to this, Go back to, Put back and History.
  5. An older version marks what it changed, against the version before it, in the tree (Only changed narrows it), and a changed file opens whole with its changes in place, ↑ ↓ to step between them: the same as main's versions in the workspace view.

What changes

  1. Edit opens the skill's own page, ready to write in, not a separate screen. The breadcrumb ends in draft ▾ (the versions menu, with the draft at its top), so you always know you are on the draft and can look at a published version from the same menu.

  3. SKILL.md's header is two fields, Name and Description; the version line goes, since publishing sets it, and the Publish dialog says which version it makes.
  4. Checks are one line at the foot; a problem is shown at its line in the file, and Publish says what it is waiting for.
  5. Discard draft moves into ⋯; Ask an agent to edit and Publish… stay as they are, with the same dialogs.
