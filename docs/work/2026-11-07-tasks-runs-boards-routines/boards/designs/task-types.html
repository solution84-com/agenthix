1Settings gets tabs; Task types is one
General · Task types · Custom fields · Runs and finished tasks. Today’s sections stay under General; the run time limit and archiving under their own tab.		Task types and their columns live in Settings. Settings is long already.
2One row per type, read across the states
For each type, its columns under the state each sits in. Feature request has two In progress columns, Building and Testing. Every state has at least one column in every type.		D10: a type’s columns each sit in one task state; setting the state directly lands on that state’s default column, so each state needs one.
3Task and Epic are built in
They can be renamed (the Name field on their columns page) and their columns edited, but not deleted: their ⋯ has Delete greyed, “Every project has Task and Epic”. Epic is marked “never run”. A new task starts as a Task unless you pick another.		D10, D12. The default for New task is Task: no setting for it.
4New task type
Opens New task type: from a Library template, or blank. The page’s one filled button; on the phone, the first item in the top bar’s ⋯, above “Website relaunch menu ›”. A Viewer sees it and every ⋯ greyed: “Viewers can’t change the project’s task types.”		D16: types are per project, from Library templates.

A task type’s columns, each in a task state

Editing one type’s columns. The four task states are fixed lanes; the type’s columns sit inside them, ordered within each, one marked the default. Drawn with ⋯ open on Testing and the tooltip of Shipped’s greyed ✕.

1The type’s name and mark
Rename, and pick its mark. Built-in types can be renamed too; they stay Task and Epic underneath. On the phone the page is a form: ✕ cancels, Save is the top bar’s one filled button.		D10.
2Four lanes, the task states, fixed
Backlog · To do · In progress · Done, in that order. Columns are drawn inside the state they sit in, so the board’s left-to-right order always follows the states.		D2, D11: the states are built in; D10: each column sits in one.
3Several columns in one state; one is the default
Building and Testing both sit in In progress; Building is its default: where a task lands when its state is set directly (from Tasks, the Task state board, or a type change). Drag ⠿ to order within a lane; a phone has no drag: Move up and Move down are in the column’s ⋯.		“Lands on that state’s default column”; defaultForState.
4Every state keeps a column
The last column in a state can’t be removed; its ✕ is greyed with why: “Each state needs a column: a task set to Done lands on it.”		Without one, setting that state would have nowhere to land.
5Moving a column, or removing one, says what happens to its tasks
⋯ on a column: Rename, Make default for In progress, Move up, Move down (the phone’s way to order), Move to another state…. A centred dialog names the tasks whose state changes, or the column they move to. Nothing changes without it.		Done always means done (D2): a column moved to Done makes its tasks Done.

A new task type, from a Library template

Pick a Library template (or Blank, one column per state), name it, create it, then edit its columns on A type’s columns. On the phone it is a focused form: ✕ cancels, Create type is the top bar’s one filled button; the whole template card picks it, not only its radio.
