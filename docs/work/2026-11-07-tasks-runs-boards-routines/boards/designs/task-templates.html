1Add to a project
The page’s one filled button, top right; ⋯ beside it holds Export and Remove… as on every template page. On the phone, the first item in ⋯ (tinted: it is the screen’s adding action); Remove… is last, in the danger colour. It opens the confirm step below.		D16; TM1. The Library already names this place’s actions this way (AssetPage: “Create an agent from this”, “Use this team”).
2What it holds
Task types with their columns, each column under the task state it sits in (the same four-state layout as Settings › Task types), then custom fields with their options. Columns are column chips; options are neutral chips, as a field’s options are shown elsewhere. The line under it says what never comes with it: tasks, boards, skills.		D16, D10; spec/data-model.md “Library”: a task template holds types with columns and fields with options.
3Who made it, and its version
The identity, the version in use and the signer, as every Library page writes them (publisher/name · version · Signed by …). Versions and About on the right: who published each version and when, where it came from. The organisation signs, not a person.		ADR-0157 (an asset, SemVer, one pinned version), ADR-0158 (the publisher is the verified signer; the organisation signs).
4Projects made from it
Which projects added it, with the version each was made from. The existing words stay: things made from a template are their own, and updating the template doesn’t change them. Here none yet; after the install below it lists Website relaunch (made from 1.1.0).		D16: what it adds is the project’s own.

Adding a task template to a project: the confirm step

A centred dialog over the Library page. Pick the project; the dialog then lists what will be added and what will be left alone because the project already has one of that name, before anything is changed. The button says exactly how many types and fields it adds. Drawn for Website relaunch, which already has a field named Channel; then a project with nothing in the way, and a project that has everything already (the button greyed, its reason in its tooltip). The phone draws it as a focused form.

Publishing or proposing a project’s types and fields as a task template

From Settings › Task types (and the same item on Custom fields): Publish as task template… in the page’s ⋯, beside New task type. It opens a form page: name, description, and a tick for each type and field to include, each type with its columns and each field with its options. Publishing makes version 1.0.0 in your organisation’s Library and opens its Library page; no message. Drawn for Sam Okafor, a Library maintainer. Anyone else who may work in the project sees Propose as task template… in the same place: the same form, with Send for review in place of Publish, and a Library maintainer reviews the proposal and publishes it, as for skills. An agent never does either: it drafts or proposes, and a person publishes.

1Name and description
The name becomes the identity (fernhill/launch-work) and the version is the first, 1.0.0. The description is written in the one Markdown editor. Reached from ⋯ › Publish as task template… on Task types and on Custom fields; on the phone it is the second item in ⋯, after New task type.		TM2; D21 (one editor wherever text is written); ADR-0157 (identity and SemVer).
2Tick the types to include
Each type is the Task types row: its columns under the state each sits in. Bug and Feature request are ticked.		D16.
3Task and Epic are not offered
Their ticks are greyed, with “Every project has Task and Epic, so they are not shared” as the tooltip (on the phone, as the row’s line).		D10, D12: every project has them, so installing them would always be left alone.
4Tick the fields to include
Each field with its options. Launch stage is ticked; Audience and Channel are not.		D16.
5What it holds, and what follows
The counts in words, what never goes with it (tasks, boards, sprints), who signs it, and that whoever adds it gets their own copy. The project’s own types stay as they are and don’t start following the template.		D16; ADR-0158 (the organisation signs).
6Publish
The one filled button, top right; Cancel outlined. On the phone the form’s top bar: ✕, the title, Publish. Greyed while nothing is ticked, with “Tick a type or a field to publish” as its tooltip. Publishing is for administrators and Library maintainers, as for every Library asset; anyone else proposes instead (7).		ADR-0157: Library maintainer is the only role beside administrators, and publishes every asset.
7Propose as task template…
For anyone else who may work in the project, the same ⋯ item in the same place, enabled. It opens the same form (name, description, ticked types and fields); the one filled button reads Send for review, Cancel is outlined, and the form says a Library maintainer reviews it and publishes it. The version line reads “the first version, 1.0.0, when a maintainer publishes it”. On the phone: ✕, the title, one filled button, and the ⋯ entry reads Propose as task template…. The proposal waits in the Library for a maintainer, as skill and team template proposals do. An agent never publishes: it drafts or proposes, and a person publishes.		Owner, 7 Nov: task templates follow the rules of skills; ADR-0157 (maintainers publish); agents draft, people publish.
