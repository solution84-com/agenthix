The Cloud section on HQ's page

Spec part D, fourth bullet; part C1. The one standing place to find Cloud: a Cloud section on the Fleet Console's HQ page, in each state — not connected, connecting with the code, waiting for an early-access place, connected, and HQ on Agenthix Cloud — with one Connect wording that never assumes the person is new, and the count of people who asked.

Today

  1. HQ's page: the title with HQ's state, the actions (Open HQ, Plan maintenance, Back up now, Logs, Erase), the HQ facts, then a bordered Cloud section, then the machine HQ runs on.
  2. Not connected, the section says Connect Acme Robotics to run sites on Agenthix Cloud and to reach this Fleet Console from elsewhere. On the command line: agenthix cloud connect — a command that does not exist — and offers Connect to Agenthix Cloud ↗.
  3. Connecting (built by the connect lane): the code to check in large type, Approve on Agenthix Cloud ↗, Cancel and Waiting for approval…; refused, expired or failed requests show in a notice and Connect is offered again.
  4. Connected: Connected as <name> and Disconnect…. Through remote access the section is read-only.
  5. There is no early-access state, no state for an HQ that Cloud runs, and nothing says how many people asked.
Before
A command-line hint that points nowhere, and two states.
After
The command-line sentence goes: connecting is done here. Not connected, the section says in one paragraph what Cloud gives the organisation, the count of people who asked (only when anyone has), and Connect to Agenthix Cloud ↗ with a line that covers both a new and a returning person (signing in there or making an account). New states: Waiting for an early-access place (with Leave the list…), and HQ on Agenthix Cloud (no Disconnect; the connection is Cloud's own). Connected adds the person's own Cloud link, pointing to Your account, and how many members have linked.
Why
Spec D, and the brief's fix: nothing on screen may send a fleet admin to a command that does not exist. One wording for Connect, because the spec forbids assuming the person is new to Cloud.

Links out to Cloud, and back

Spec part D, seventh bullet. Every link to Cloud carries where to return to, what the person was doing and their entry point — and nothing about the organisation or the person. The Fleet Console picks the task up on return (state 5 above).

Today

  1. Only Approve on Agenthix Cloud ↗ links out today, to the page Cloud named (checked to be on Cloud's address).
what a link out carries
https://cloud.agenthix.com/start?return=http%3A%2F%2F127.0.0.1%3A4300%2Fhq&task=connect&from=fleet-console-hq
returnThe page to come back to. From the Fleet Console, its local address and path; from HQ, HQ's address and path.
taskWhat the person was doing: connect, switch, start-organisation, link-account, offer-site, offer-backups, offer-address.
fromThe entry point: hq-menu, fleet-console-menu, hq-settings, fleet-console-hq, fleet-console-backups, fleet-console-address, hq-no-site.
neverThe organisation's name or id, the person's name, username or id, counts, or anything read from HQ.

Built from · One function in @agenthix/core, say cloudLinkOut(base, {{ return, task, from }}), used by hq and console-web, with a test that the result has exactly these three parameters. The base is the configured Cloud address (AGENTHIX_CLOUD_URL), passed to the browser; nothing is fetched to build a link.

Open, decided conservatively for the owner: A link from HQ carries HQ's own address as return, which says which HQ the person came from. The spec asks for where to return to, so it is drawn; the alternative is for HQ's links to carry only the path and for Cloud to send the person back with the browser's history.
