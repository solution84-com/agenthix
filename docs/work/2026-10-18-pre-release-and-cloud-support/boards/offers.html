Where Cloud removes a limit

Offers where Cloud removes a limit — fleet admins only

Spec part D, fifth bullet. One dismissible line, gone for good once dismissed, on no site available, backups kept on the machine and domain and HTTPS. None on upgrade notices; members never see one.

The line itself

Each offer is one line: Cloud's mark, one sentence saying what Cloud changes about the limit on this screen, a link out (task=offer-…, see Links out), and × to dismiss. It is outlined with a dashed border so it reads as an aside, not as a notice about the fleet. Dismissing one offer hides that offer for that person everywhere it appears, for good; the others stay.

Built from · A new presenter CloudOfferLine in @agenthix/ui/primitives (drawn by HQ and the Fleet Console): {{ sentence, linkLabel, href, onDismiss }}, with CloudMark's sunrise, border-dashed border-border, bg-surface-1. Each app writes its own words. Data: hq stores dismissals per person (a list of offer names: site, backups, address); hq reads it for its own screens and the Fleet Console reads and writes it through the console link (cloud.offers / cloud.dismissOffer, new). Shown only to a person holding the fleet admin role, and never by calling Cloud.

Where no offer goes

  • Upgrade notices in HQ or the Fleet Console (HqUpgradeNotice, the shell's notices): none.
  • Any screen a member sees, other than what the switcher and Settings › Sign-in say about their own sign-in: none.

Open, decided conservatively for the owner: Whether an offer still shows once the organisation is connected. Drawn as shown while the limit lasts, connected or not, since connecting alone does not remove a limit. Also whether dismissing should be per person (drawn, as the spec says gone for good and only fleet admins see them) or for all fleet admins at once.
