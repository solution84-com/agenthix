Organisation › Infrastructure — where HQ runs

Spec part D, fourth bullet: HQ's Organisation › Infrastructure says where HQ runs and links to the one standing place to find Cloud, the Fleet Console's HQ page.

Today

  1. Infrastructure (organisation admins) lists HQ (Version; Address and environment), Where work runs (each site), Storage (Database; HQ's own files) and More (GitHub App; Logs and diagnostics), each a row with one line that opens its page.
  2. Nothing says whether HQ is self-hosted or run by Agenthix Cloud.
Before
No line about where HQ runs.
After
A first row in the HQ group, Where HQ runs, with one line in each state: self-hosted and not connected (pointing to HQ's page in the Fleet Console), self-hosted and connected, or on Agenthix Cloud. It opens Organisation › Infrastructure › HQ, whose new first block says the same and links to the guide's Agenthix Cloud page.
Why
Spec D. HQ does not know the address the Fleet Console is opened at (it is on a machine's 127.0.0.1), so HQ names the place in words and links to the guide, rather than to a Fleet Console address it cannot know.

Data: a query, say getWhereHqRuns, answering {{ hosting: 'self' | 'cloud', machineName, connectedAs: string | null }} from the CloudConnection row and whether HQ's machine is enrolled with Cloud (relayed by its host service).
