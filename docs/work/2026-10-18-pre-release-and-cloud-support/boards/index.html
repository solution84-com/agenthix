What the platform shows of Agenthix Cloud, and the pledge

The boards for part D of the design spec (spec.md, beside this folder): every new screen and state, drawn before it is built. Each board shows Today, numbered, then Before, After and Why, then each state as one full-width screen. The switch at the foot of the menu flips every screen between light and dark; the colours are the product's design tokens. A Built from line under each feature names the components and the data it needs, for the lanes that build it.

The rule they follow

  • Members see what Cloud gives them and can ask for it: one account, switching between organisations, an organisation of their own.
  • Fleet admins also get an offer where Cloud removes a limit they have hit — one dismissible line, gone for good once dismissed.
  • An HQ that is not connected never calls Cloud, and nothing is offered before Cloud can deliver it. Every state on these boards is read from HQ's own records — whether HQ is connected, whether the person's account is linked, whether HQ's machine is enrolled with Cloud — never by asking Cloud (ADR-0130).
  • The public pages (sign-in, invitation) carry no link to Cloud.
  • Links out carry only where to return to, the task and the entry point.

Decided on these boards

#Decision
D1Sign in with Agenthix Cloud sits under the password form, behind an or divider, so the password stays the first way in.
D2A Cloud account that nobody in this HQ has linked cannot sign in; the person is told to sign in with their password and link it in Settings › Sign-in.
D3The switcher is a row under the mark at the top of HQ's menu and under the machine badge in the Fleet Console's; it lists only this organisation, ticked.
D4Ask a fleet admin lives in Settings › Sign-in; the switcher points there. The count of people who asked shows in the Fleet Console's Cloud section, only when it is more than none.
D5The Fleet Console's Cloud section loses its command-line sentence; one Connect wording: Connect to Agenthix Cloud ↗ — you approve the connection on Agenthix Cloud, signing in there or making an account.
D6An HQ that Cloud runs shows its connection without Disconnect; it ends only on Cloud.
D7Offers are a dashed line with Cloud's mark, a sentence, one link and ×; dismissal is per person and per offer, kept by HQ, and applies in both portals.
D8The pledge card is last on Home, shown from the first sign-in until dismissed.

Open for the owner — each drawn the conservative way

  1. The early-access state is not in the connection protocol (C1 knows approved, refused and expired). Drawn as a fourth outcome HQ keeps until a place opens.
  2. The invitation's Cloud path makes an account with no password (drawn); or should it still ask for one?
  3. Setup's first step shows the greyed button on a fresh HQ (drawn, as the spec says always); or leave it out until HQ is connected?
  4. Infrastructure's link to the Fleet Console: HQ cannot know the Fleet Console's address, so the line names the place in words and links to the guide.
  5. Links from HQ carry HQ's address as the return place, which says which HQ the person came from.
  6. Offers after connecting stay while the limit lasts; dismissal is per person, not for every fleet admin.
  7. The pledge card's two lines are placeholders to be written with the pledge page.
  8. You asked is for good, even if HQ later connects and disconnects.
