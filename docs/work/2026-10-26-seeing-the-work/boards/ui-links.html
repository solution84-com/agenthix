T2 · Links and mentions that open a file

One stable link per file (R5), the same from every surface, opening the file in place. Files and workspaces already have one: the place's own address with the tool and the file (?tool=files&file=, ?workspace=&wfile=). A task's working files gain the same shape.

The link

After · proposed
Where the file isIts link
A project's Fileshq.example.com/projects/ALPHA?tool=files&file=reports/q3.pdf
A workspacehq.example.com/projects/ALPHA?tool=workspaces&workspace=<id>&wfile=src/app.ts
A task's working fileshq.example.com/projects/ALPHA?task=WEB-42&file=notes.md new
Your spacehq.example.com/chat?tool=files&file=drafts/plan.md
  • Never a site, a relay or a ticket: those are decided when it's opened (board 3). A link copied today still opens after the site moves.
  • Someone who can't see the place gets the place's usual "not found", never the file's name.
  • A file that's gone: "This file isn't here any more", with its folder.

In a conversation

After · proposed
I've put the report in 📄 reports/q3.pdf and the raw numbers in 📊 reports/q3-data.csv.

An agent's reply. A path it writes, files/… as today's Mention inserts, or artefacts/… as today, becomes a chip.

Can you check 📊 q3-data.csv against last quarter?

Mention, from a file's header (F2), puts the same chip in the message being written. The agent receives the path, as today.

  1. A chip opens the file beside the thread, where a shown part opens today (ShownViewer.tsx: beside on a wide screen, a sheet from the bottom on a phone), in F2's frame.
  2. Chips are made by extending today's artefact-link interception (useArtefactLinks.ts) to files/ and workspace paths, so old messages gain them too.
  3. A chip for a file that's gone is struck through, with its name kept.

Anywhere else

  • Copy link in a file's ⋯ (F2) gives the link above, for a task's description, a comment, or outside Agenthix.
  • Pasted into Agenthix, a link to a file shows as the same chip.
