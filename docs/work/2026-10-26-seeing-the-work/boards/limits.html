8 · Security and limits

Q5, settled on 25 Oct (D12–D15). What the relay design trusts, what could go wrong, and what stops it. Every defence was checked again as boards 3–7 were drawn.

How many doors?

hq's machine keeps one front door with two names, as it has today. hq publishes one port (adr-0067); hq-web behind it sends each name to its own place.

  • No new door on hq's machine, and less behind the one there is: file traffic stops reaching hq at all.
  • A bare address has one name only; hq's relay answers on a path of it (D17). Still one door.
  • A further relay on a machine of its own (relay-2) is the only new door: opt-in, for an organisation that has outgrown hq's relay, on a machine with no files and no decisions to attack.
  • Sites have no door at all, before or after.

To decide, one at a time

S1 · May a relay see the bytes? Decided: yes (D12)

A relay is trusted like a site, because both are fleet members. A site sees every file it holds; asking the relay to be blind would ask more of it than of the site, so the rule is the same for both: whoever runs a fleet machine is trusted with what it holds or carries. An organisation that has its fleet hosted for it trusts the host with sites and relays alike. Blind relays (TLS passthrough) were considered and dropped as inconsistent and costly.

S2 · How the browser carries the ticket. Decided: in the link (D13)

The ticket is part of the link, for example files.example.com/t/<ticket>. It's good for a few minutes and reusable until then, so a PDF viewer can fetch page by page. That's the way the files address already serves uploads (adr-0114), so one pattern serves every file. It's sent with no-referrer and never logged by a relay or a site. Rejected: a cookie, which is third-party inside hq's page and already blocked by Safari; a request header, which a PDF frame or a download can't send.

S3 · The caps. Decided (D14)

Decided 25 Oct. Text is held at 1 MB on purpose: across the platform's own 5,191 text and code files the median is 3.5 KB and 99% are under 25 KB, so a text file larger than 1 MB is a smell, not a case to serve. A file that size gets Download; if a real need appears, it's a change request (pagination, say), not a raised cap. The other values are starting points an admin can change. Past a preview cap, the preview shows what fits and says so, with Download beside it. Nothing is refused that could be downloaded.
