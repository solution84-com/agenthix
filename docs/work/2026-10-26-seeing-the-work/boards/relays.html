5 · Relays: hq's relay, more relays, placement

Level 2. A relay is a fleet member that carries file bytes and decides nothing (D5). hq's relay is always there and just works (D16). More relays are added the way more sites are, and hq places sites on them (D9). The example organisation owns hq.example.com.

Who dials whom

  • A relay dials hq on the control channel, like any fleet machine: it reports it's alive, its load, and gets nothing else from hq but which sites may connect.
  • A site dials its relay, when hq tells it which (step 3 below), and keeps one line open. Requests come down it; bytes go up it. The protocol is the content channel's stream multiplexer, reused (core/src/protocol/contentMux.ts).
  • Both ends prove who they are. The site presents a pass hq signed (this site, this relay, an expiry); the relay presents its enrolled identity, which hq named to the site. A rogue relay gets no connection (T4); a relay accepts no site hq didn't send.
  • Browsers reach a relay only with a ticket (board 3).

Placement (D9)

  1. Default: every site is on hq's relay. One relay, nothing to decide.
  2. When a relay is added, hq moves sites onto it until the load is even: by sites per relay at first, by bytes carried once there's history.
  3. hq tells a site its relay on the control channel (a typed message, with the pass); the site dials it. A move is the same message with another relay: the site opens the new line, then closes the old one, so open files carry on.
  4. When a relay goes quiet for longer than a minute, hq moves its sites to the others. If none is left, they wait for hq's relay.
  5. An admin can pin a site to a relay, for example one in the same region as the site and its people. A pinned site isn't moved; if its relay is down, its files say so (D17).

When a relay is down

Relays alone carry file bytes (D17). Opening a file whose site's relay is down answers at once, without trying: "Files on office-server can't be opened right now: relay-2 isn't answering." Listing and browsing still work, because they're typed requests through hq, not file bytes. The Fleet Console marks the relay, and for hq's relay that's the same machine as hq, so it's already an outage worth seeing.
