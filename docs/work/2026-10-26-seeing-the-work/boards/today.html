What's missing

  • No renderer boundary. Every new format means editing the switch.
  • Binary and over-cap files can't even be downloaded. The menu's Download appears only for Markdown, code and images.
  • Code isn't highlighted, though react-syntax-highlighter is installed and unused.
  • No PDF, no CSV table, no JSON view. CSV and JSON show as plain text.
  • Task attachments are listed but never previewed, and no task links to its own folder.
  • Mention inserts plain text files/<path>, not a link.
  • Every byte passes through hq, in memory and as JSON. That's the load D4 moves off hq.

What there is to build on

  • Access is checked on hq before any byte is read (assertLocationAccess).
  • Markdown already renders without raw HTML, so untrusted Markdown can't run script.
  • A files address with no cookies and locked-down headers, for task attachments (adr-0114). Its signed links last 5–10 minutes (hq/src/server/files/fileLinks.ts).
  • Files already have addresses in the URL: ?tool=files&file=, ?artefact=, ?wfile=.
  • A registry pattern to copy: PlaceTool { id, label, render } in places/placeTypes.ts.
  • The content channel already streams. A caller can pipe it rather than collect it.
