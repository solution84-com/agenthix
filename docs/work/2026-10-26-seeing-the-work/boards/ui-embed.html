T3 · Embedded: in Markdown, tasks and conversations

The second way a file is shown. Opened (F2, T1) is a file on its own, in a panel or full screen. Embedded is a file shown inside something else: an image in a Markdown page, a chart in a task's description, a picture in a message. The same ticket and relay carry the bytes; only the size and the controls differ. Raised in review. Scope decided (D19); where a person's own images go, D20.

Today

Before · today
  • Markdown images aren't resolved. ![](charts/q3.png) in a file or a knowledge page points nowhere; an image on another website loads straight from that website, telling it who's reading.
  • Conversations carry no images. A person can't paste or upload one; an agent can only mention a path.
  • A task's description is text; its attachments are a list (T1).

In a Markdown page

After · proposed

Q3 summary
Revenue grew 6% on Q2, led by the north region.
charts/q3.png

The full numbers are in 📊 q3-data.csv · 84 KB

🖼 Image from example.org · Load
  1. A relative path (![](charts/q3.png)) resolves against the page's folder, in the same place, and embeds through the relay. A path outside the place shows as a broken image with its name.
  2. An image tag, <img src="charts/q3.png" alt="Q3" width="600">, is drawn the same way, so an image can be sized, as GitHub's Markdown allows (D23). It's the only HTML Markdown accepts: only src, alt, width and height are kept, and every other tag stays text. Its src resolves like a Markdown image.
  3. A link to another file becomes the card, or a chip inline.
  4. An image on another website isn't loaded on its own: it's shown as "Image from example.org · Load", so opening a page never tells another site who's reading. One click loads it.
  5. One Markdown embed, everywhere Markdown is drawn (D19): Markdown files, knowledge pages, a task's description and comments, and agents' replies in conversations. All of them go through MarkdownMessage today, so the embed is added once, there.

An agent's reply showing an image it made.

  1. A message carries a reference, never the bytes: the file's place, path and version. The image is a file like any other, so it can be opened, downloaded, mentioned and found in Files later.
  2. An agent shows an image by writing Markdown, ![flow](files/diagrams/flow.png): its replies are already drawn as Markdown (ReplyBody.tsx uses MarkdownMessage), so the Markdown embed covers them with nothing new. Paths are read from the conversation's place, the same files/… form Mention inserts. A path it only mentions stays a chip (T2).
  3. Stretch: a person adds an image by pasting, dropping or choosing a file. It belongs to the conversation's place but is kept outside what runs mount, as knowledge is: people see it through the relay, agents only through Agenthix's tools for that conversation, never on the file system (D20). It stays in the room: only people in the conversation see it, today its owner, later whoever is invited; Save to Files or a task attachment shares it beyond (D21). The message refers to it like any file.
  4. Whether the agent can see an image a person sends (a model that reads images) is the conversation's work, not this epic's; this epic makes the file exist and show.
  5. Files keep no history on a site, so a message shows the file as it is now. If it changed after the message was sent (the reference's version differs), a small line says "Changed since this message".
