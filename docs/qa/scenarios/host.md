# Scenarios — `host/`

> Module contract: what `host/` (the host service, run as the container `agenthix-host` on every machine — `<namespace>-host` for an install under another namespace — and its command line `agenthix …`) promises the machine admin who types its commands, and the Fleet Console that sends it commands. Flat capability list.
> **Scenario ids are unique across every file in this directory**, not per file, because a test cites a scenario by its id alone; the next free id for all of them is `next-sc` in [`hq.md`](hq.md). Ids are append-only: assigned once, never reused or renumbered.
> Written on 2026-10-16 from the finished code at the close of the host management unit. The stories these fulfil are in [`../stories/host.md`](../stories/host.md). What the Fleet Console does with the host service is in [`console.md`](console.md) and [`console-web.md`](console-web.md); HQ's side is in [`hq.md`](hq.md), under "Host management — HQ's side".

The host service is the one authority over its machine: it installs, runs, upgrades, backs up, moves and erases HQ and the site there through Docker. A machine admin reaches it with `docker exec -it agenthix-host agenthix <command>`; the Fleet Console reaches it only with signed commands that HQ passes on sealed.

Tests marked as container tests (`*.container.test.ts`, run with `npm run test:container`) need Docker and the built image.

## Installing

- **SC-816** — `agenthix install` asks one question, HQ's address, with the default in brackets taken on Enter, asks again when the answer is not an address, asks nothing once HQ is installed, and stops saying how to answer when there is nobody to ask; it then starts HQ, then its site, connected by one pairing secret, and the Fleet Console beside HQ, and ends with the shortcut to type and one link for the first account. · fulfils AC-287a
- **SC-817** — Install refuses, before touching Docker and changing nothing, an address a browser cannot use, another address once HQ is installed, a host service started without the figures volume (naming the line to add) or without its state folder's place on the machine; it says which image it could not get, names the next step when HQ does not answer, and finishes saying so when the site has not connected yet. · fulfils AC-287b
- **SC-818** — Running install again changes nothing already set and makes no second first-account link once HQ has people; every setting and secret it writes is readable by its owner only and none is printed; the first-account link is taken from HQ's data, not from its log. · fulfils AC-287c
- **SC-819** — An `https://` address is served through a front door with HQ listening on `127.0.0.1` at its published port; only hq-web is published, where the settings say; hq-web is given HQ's address; uploaded files get an origin of their own — `files.localhost` on HQ's port for a local address, `files.<host>` for a domain, none where the address can have no subdomain — passed to HQ as `FILES_ORIGIN`. · fulfils AC-287a
- **SC-820** — A release build trusts a list of publishers — each a registry, its image names, a repository and its publishing workflow; one entry today — and checks each image's signature with cosign, before fetching any, against the publisher whose names the image carries, at that version's tag (trying each when two share a name): an image no entry names is refused without being checked, and an unsigned image, a missing one or one whose signature cannot be checked stops the check at once; it fetches and runs each image by the digest the signature covers and never lets compose fetch one; it refuses an unsigned image or one signed by someone else, fetching and writing nothing, refuses images built on a machine, and fails closed, naming the next step, when a signature cannot be checked. A development build runs the images built on the machine unchecked, says so, and still checks a published image. · fulfils AC-287d
- **SC-821** — Every stored name — containers, volumes, networks, the firewall table — is derived from the namespace recorded in a private file at the host service's first start; the record is read back whatever the code now calls the product and is never overwritten by one it cannot read. · fulfils AC-287c

## Knowing how the machine is doing

- **SC-822** — `agenthix status` opens with the machine, how it is hosted and the host service's version, then says how HQ and the site are, each in a sentence that ends in what to do next: nothing installed and how to install; a fresh HQ and its first-account link; HQ starting; a stopped HQ or site losing nothing and how to start it; why the site is not connected, in words, with a next step; the agents working. It never prints an internal word and keeps every line within a terminal's width. · fulfils AC-288a
- **SC-823** — `agenthix` lists only the commands it has, grouped, in their `docker exec` form; a command it does not have is refused, pointing at help; when the host service does not answer, the command says how to restart it. · fulfils AC-288b

## Keeping agents off the machine

- **SC-824** — The agent protections shut the machine's own ports, the ports other containers publish, and every cloud provider's metadata address to the agents' address range — and on Docker Desktop also the computer Docker runs on — touching nothing else, so ordinary internet access stays; they are one table of the host service's own, replaced whole, and have no setting. · fulfils AC-289a
- **SC-825** — The protections are checked at start and every minute and put back when something removed them; while they do not hold — no right to change the firewall, no firewall tool, rules that cannot be built — the host service says why, `status` says so and where to look, and the site starts no agent, in a new container or one already up. · fulfils AC-289b
- **SC-826** — `agenthix capacity` shows each container's ceilings and what the machine has; `capacity set` changes only what it is given, refuses ceilings that could not all fit the machine's memory or more processors than it has, and stores them for the owner only; the site gives each container the machine's ceilings and may narrow them by its own setting, never raise them. · fulfils AC-289c

## Backups

- **SC-827** — Each machine backs up HQ and its site at 02:00 by its own clock, once a night, sealed to the machine and labelled with the night before; it catches up only the last missed night, once, never just before the next is due and never a night before the site was installed; a failed night is tried once; the last 14 nights are kept on the machine. · fulfils AC-290a
- **SC-828** — A sealed backup opens only with its key, every part as it was; nothing it holds can be read in the file; a changed description, a changed byte or a backup cut short is refused; its description can be read without the key; it can be passed to another holder without being decrypted. · fulfils AC-290a
- **SC-829** — `agenthix backup location <path>` refuses a folder that does not exist or cannot be written before any key is made, shows the key once, and sets the location only once the person says they stored it, keeping only the public half; each backup is then copied there and opens with the person's key and not the machine's. With no path it shows the current one, or says none is set and what to run. · fulfils AC-290b
- **SC-830** — What a Fleet Console may ask includes taking a backup now and exporting one, and never setting the backup location or any other of the machine's own backup operations. · fulfils AC-290d
- **SC-831** — An export is sealed to a key made for it, of which the machine keeps nothing. One made for the Fleet Console is held apart from the machine admin's exports, read back a chunk at a time only with its key, leaves the machine once downloaded and is then refused in words, is removed a day after it was made if nobody downloads it, and never reaches an export the machine admin made. · fulfils AC-290c
- **SC-832** — `status` says when the last backup was and where its copy went, and says plainly when the backups would die with the machine; the machine's figures carry the last backup, its copy and export and whether a location is set, never its path; a suspended machine takes no nightly backup and records no failed night. · fulfils AC-290a, AC-290b
- **SC-833** — `agenthix restore --from <folder or file>` on a machine where nothing runs lists the nights without a key, refuses a wrong key or one that is not a key in words, changing nothing, refuses a backup of another namespace or a newer version, and brings back HQ and its site — secrets, databases and folders; it is refused where HQ already runs, pointing to the Fleet Console. On a machine that runs them, a restore first backs up what is there. · fulfils AC-291a
- **SC-834** — A site's backup carries the credential the site proves itself to HQ with. `agenthix restore --from <…> <hq address> <code>` warns before it restores and changes nothing on no; a site's backup given without a code is refused, saying what is needed, before any key is asked; the machine joins saying which backup it restores, renews the site's credential at HQ and only then starts the site; it writes nothing when HQ says the site is connected from its machine, takes away what it wrote when HQ refuses the renewal, restores nothing on the Fleet Console's word alone, and is refused on a machine that already answers a Fleet Console. · fulfils AC-291b

## Upgrades

- **SC-835** — An upgrade of HQ and its site refuses an unsigned image before anything stops, is fetched or is backed up; it checks, fetches, stops, backs up, switches to the new pinned images and checks they are healthy, and rolls back to the previous images and the backup when HQ does not come up healthy or its site does not connect; it changes nothing when the backup cannot be taken; it goes forward only, never past the host service's own version, takes the site no further than its HQ, and does not upgrade a development build; one a restart cut short is finished or put back. · fulfils AC-292a
- **SC-836** — `agenthix hq upgrade` takes the newest published version, asks, and schedules it five minutes ahead so HQ gives notice; `--at` and `hq schedule upgrade` schedule it later; it offers no upgrade when the published versions cannot be read and says when HQ is on the newest; afterwards `status` says it rolled back, why and where to look, and says when a fix or a new version is ready. · fulfils AC-292a
- **SC-837** — Automatic fixes are on by default in the window Sunday 02:00–04:00: the newest fix — a later patch of the same major and minor version — is scheduled for the start of the window as a scheduled change; a new minor or major version, or a fix that was rolled back, never applies by itself; turning them off cancels what they scheduled; they move with the window and leave alone an upgrade someone else scheduled. · fulfils AC-292b
- **SC-838** — The host service switches itself to a newer version through a launcher started from its own image with the checked image's id: the launcher stops the old one before starting the new, starts it with the settings recorded from Docker, removes the old one once the new answers as its version, and puts the old one back otherwise; it refuses an image the host service did not check and a version that is not newer, carries on after a restart partway, and says so with the commands when the old one cannot be started again. With the launcher off, the switch is by hand with the printed commands. · fulfils AC-292c

## Scheduled changes on the machine

- **SC-839** — A change is refused for a time that has passed or a kind this version cannot schedule yet; otherwise it is held, HQ is told through its control socket (or the site, on a site's own machine), and it runs at its time; a changed time runs at the new time only, a cancelled change never runs, and a notice HQ did not take is sent once HQ answers again. Across a restart a change whose time came while the host service was down runs if it is not long past and is reported missed otherwise; a change that fails is put back and reported failed with why. Each change is sent to the Fleet Console, sealed and signed, as soon as it is scheduled and as it moves on. · fulfils AC-293a, AC-293b, AC-293c
- **SC-840** — A time is read as a person types it, in the machine's zone, with or without the weekday and the year, and said back with how far off it is; a weekday that does not match its date and a date the calendar does not have are refused in words. `agenthix scheduled` lists what is scheduled, `schedule change` moves one and `schedule cancel` cancels it, each in words. · fulfils AC-293a
- **SC-841** — A scheduled change whose site or HQ is no longer on the machine ends as cancelled with the reason; disconnecting from the Fleet Console cancels every open change. · fulfils AC-293b

## Suspend, resume and erase

- **SC-842** — `agenthix hq suspend` stops HQ and its site, removes nothing, and members are told; `hq resume` starts them again and forgets the suspension; a site is suspended alone with `site suspend`; `--at` holds either like any scheduled change; `status` says how to start what is suspended. · fulfils AC-294a
- **SC-843** — Erasing HQ is refused unless HQ's address is typed exactly; it takes a final sealed backup and removes nothing if that fails, removes the running data, keeps the backup 30 days, and ends what else was scheduled as cancelled; `hq restore` brings it back within the 30 days, after which it is purged with the backup location's copies (an entry whose copies cannot be removed is kept, saying why). With `--on`, everyone sees the countdown, and cancelling leaves everything as it was. · fulfils AC-294b
- **SC-844** — Erasing a site is refused where the site carries HQ; on its own machine it asks for the site's name, and a wrong one erases nothing; it says whether HQ was told. · fulfils AC-294c

## Joining the fleet, and leaving it

- **SC-845** — `agenthix console connect <hq address> <code>` shows the machine's name and fingerprint to compare, then the Fleet Console's, and pins the Fleet Console only once its binding proves it holds the code; the code never reaches HQ, only a lookup derived from it; nothing is pinned when HQ puts its own key in the Fleet Console's place or hands over something that is not a credential; it says in words when the code ran out, was used or was not taken, gives up when HQ goes quiet, stops on Ctrl-C keeping nothing, refuses a machine that already has a controller, and refuses plain `http://` across a network. · fulfils AC-295a
- **SC-846** — The claim "this machine runs HQ" is made only by the host service that runs HQ, under the binding, so HQ can neither add it nor drop it; it is not made once HQ has moved away. · fulfils AC-295a
- **SC-847** — An envelope from the pinned Fleet Console asks only the closed set of operations, on behalf of the fleet admin it names, and the answer goes back sealed to it; it cannot ask an operation that stays on the machine or speak as the machine admin. An envelope is refused, with nothing acting on it, from a key that is not pinned, when HQ made it up or changed it, a second time, once expired, after the machine disconnected, when sealed to another machine, or when it is not an envelope. The owner socket rebuilds each request field by field and is kept to its owner. · fulfils AC-295b
- **SC-848** — `agenthix console disconnect` says what happens and asks; then it forgets the pin and the credential at once, even with HQ and the Fleet Console unreachable, refuses every envelope after it, and stops the site the Fleet Console added, keeping its data; it is refused on HQ's machine; HQ's revoke does the same. · fulfils AC-295c
- **SC-849** — A machine that disconnects itself tells HQ it left: at once when HQ answers, otherwise through a one-use notice readable by the owner only, delivered once HQ answers again; it takes the credential away from the stopped site, never leaves with a credential a move released, and reaches HQ at the address its link was using. · fulfils AC-295c
- **SC-850** — At its stop signal the host service sends its Fleet Console one stop word, signed and sealed, waits for it to leave within a budget and never holds the stop past it. · fulfils AC-295c
- **SC-851** — The link to HQ's relay dials out to `/host-link` with the machine credential and nothing else, answers ping, passes envelopes on, takes revoke, opens again with growing waits, takes a silent connection for dead, and stays closed once stopped or without a pin. · fulfils AC-295b
- **SC-852** — On HQ's machine, `agenthix hq fleet-admin <user>` asks, then gives the account the role and passes on what HQ says; `--remove` takes it away, asking first; a mistyped user is named. · fulfils AC-296a
- **SC-853** — `agenthix hq console-code` asks the Fleet Console — here, or on another machine in a sealed envelope — for a handover code that hands every machine over, and never takes or falls back to a code HQ makes in its place; `--no-machines` makes HQ's own code only once agreed, and is refused while the Fleet Console runs here. `console install` starts the Fleet Console and says how many machines follow it; `console remove` asks first and removes one HQ no longer lets in, with its keys, and is refused while this machine answers it; `status` says which Fleet Console manages the machine and whether it is connected. · fulfils AC-296b
- **SC-854** — A handover certificate moves the pin only when the pinned Fleet Console signed it, keeping HQ's address and the machine credential; a chain of moves the machine slept through is followed; the Fleet Console that handed over is removed with its keys from its machine, and only once the new one holds the key that signed. · fulfils AC-296b

## HQ's address and the front door

- **SC-855** — `agenthix hq address <address>` tells HQ first, stops it, takes a backup and starts it at the new address; when HQ does not answer there it is put back at the old one and those told are told again; nothing changes when HQ does not answer to tell anyone, or the address is the same. · fulfils AC-297b
- **SC-856** — A machine, a site and the Fleet Console told that HQ moves keep the old address until the new one passes a check that it holds their record — not merely that some HQ answers — and never send a credential in the clear; `console hq-address` and `site hq-address` point a machine that was offline the same way, refusing in words an address that fails the check; `status` says what to run when a move has not completed. · fulfils AC-297b
- **SC-857** — `agenthix front-door on` warns that it takes ports 80 and 443 and defaults to no (a script needs its flag); it is refused at once while either port is in use, for an HQ at a plain `http://` address, or when its configuration does not pass, before anything is written; it serves HQ and its uploaded files from their own certificates, or rolls everything back when one cannot be had. `off` frees the ports; with nothing after it, it prints the steps for a web server of the machine's own; `status` shows what it serves, the earliest expiry and a renewal problem. · fulfils AC-297a

## Moves

- **SC-858** — A site moves to a new machine with its credential, its database and its workspaces, named after the new machine, and HQ reads none of it; the copy on the old machine is removed only once the site answers from the new one; a chunk changed on the way fails the restore, keeps nothing on the new machine and the site carries on where it was; when the new machine does not take over, the site comes back on the old one; the site never runs on both. The machine waiting to receive it starts no site of its own. · fulfils AC-298a
- **SC-859** — HQ moves to a new machine with its data, its site and the Fleet Console, at its new address, and never runs on both: it is read-only from the move's backup until the old machine commits, nothing is removed on the old machine before HQ answers from the new one, and when the new machine does not take over HQ comes back on the old machine, writable. `agenthix hq move recover` is refused without the confirmation that the new machine is not running HQ and while the move may still complete, and otherwise starts HQ, its site and the Fleet Console again from what was kept. · fulfils AC-298b

## The machine's way into HQ

- **SC-860** — On a fresh install the machine prints a first-account link without asking; once HQ has people it asks before making an organisation admin invitation and makes none on no; a reset link says who to give it to and who was told; a refusal from HQ is read by its code, not its words. · fulfils AC-296a

## Images, published from a pre-release too

- **SC-1052** — Images are published and signed for a release tag and for a pre-release tag (`-alpha.N`, `-beta.N`, `-rc.N`); the workflow and the host service accept exactly the same versions, and a pre-release's signer is the workflow run for that pre-release's own tag, not the release's. Versions order an alpha before a beta before a release candidate before its release, and the newest version a machine is offered is always a release, never a pre-release. · fulfils AC-335a, AC-335c · tests `host/src/images/__tests__/workflow.test.ts`, `host/src/images/__tests__/signatures.test.ts`, `host/src/upgrades/__tests__/versions.test.ts`
- **SC-1053** — A machine given both a registry username and token in its start-up settings writes a Docker configuration of its own (readable by its owner only, under the host service's state, for the registry only) and gives it to the image pull and the signature check and to nothing else; it does nothing unless both are set, removes a configuration an earlier start wrote, and no command it starts inherits the credential. · fulfils AC-335b · tests `host/src/images/__tests__/registryAuth.test.ts`
- **SC-1054** — `@agenthix/core` can be published as a package that ships its built output only, for the same tags the images are published for and by nothing else, with the least permissions the workflow needs. · fulfils AC-335d · tests `host/src/images/__tests__/corePackage.test.ts`

## Agenthix Cloud's controller

Everything below holds only on a machine enrolled with Cloud and for requests from Cloud's pinned identity, recorded as Cloud's.

- **SC-1055** — The enrolment code is read from the file the settings name only when it is a plain file, owned by root, readable by it alone, not reached through a symbolic link, written within the last hour; a file that anyone else may read is neither read nor deleted. Once spent the file is deleted and its code is never used again even if the file comes back; a file with no code, or none at all, spends nothing. · fulfils AC-333a · tests `host/src/cloud/__tests__/codeFile.test.ts`
- **SC-1056** — The host service enrols by dialling Cloud's address (https; plain http only to this machine) with a code's lookup, and pins Cloud's identity only when Cloud's binding proves it holds the code and names the same machine; it deletes the code file; a refusal, a binding made for a Fleet Console's join, or an answer for another machine pins nothing and spends the code; a connection that never opens tries again without spending it; it does nothing without Cloud's address. A Cloud code is not admitted as a Fleet Console join, and a Fleet Console join answered with Cloud's binding pins nothing. · fulfils AC-333a, AC-333c · tests `host/src/cloud/__tests__/enrol.test.ts`
- **SC-1057** — The host service reconnects to Cloud with the machine id and no secret, and does nothing until Cloud's first message, a fresh envelope signed by the pinned identity; it closes when that message is not an envelope, comes from anyone else, was seen before, or does not arrive in time (logging the reason, never the content); once open it drops envelopes from anyone else, answers sealed to Cloud alone, and keeps working while HQ is down. · fulfils AC-333b, AC-333d · tests `host/src/cloud/__tests__/link.test.ts`

A given files host is kept through a new address; with none given, uploads are downloads only; previews stay off. · fulfils AC-334b · tests `host/src/frontDoor/__tests__/givenCertificate.test.ts`
- **SC-1061** — `backup.location.set` from Cloud points backups at an S3-compatible store under the machine's own prefix, answering when the credentials lapse; the credentials (at most seven days, https, a checked bucket and prefix) are kept where only the host service reads them and the location's key only as its public half; asked again, it replaces only the credentials; neither the Fleet Console, the command line nor a machine not enrolled can set it, and the CLI shows it as set by Cloud and refuses a folder over it. · fulfils AC-334c · tests `host/src/backups/__tests__/cloudLocation.test.ts`
- **SC-1062** — Backups to Cloud's location are stored at the prefix and the backup id, listed, fetched and restored by the location's key, written again with `backup.store`, and split in parts when large; pruning treats a refused delete as expected and leaves expiry to the store; a backup is skipped, with a clear status, when the credentials have lapsed; a folder chosen on the machine is refused while Cloud has set a location. · fulfils AC-334c · tests `host/src/backups/__tests__/cloudLocation.test.ts`
- **SC-1063** — On the machine that runs HQ, Cloud's `site.register`, `site.unregister`, `account.firstLink`, `account.resetLink` and `account.adminInvite` are passed to HQ, a site's credential by its SHA-256 hash only; a request whose fields are not valid asks HQ nothing; HQ's refusals are passed on by their code and a silent HQ is answered as busy; a link is answered only when it is https and is never logged; `account.firstLink` answers who was made first once HQ has accounts; a machine without HQ answers `not_installed`; and an erase asked by Cloud is done only when it names HQ's address. · fulfils AC-334e · tests `host/src/cloud/__tests__/hqOperations.test.ts`

## Names, groups and networks on a machine (added 2026-10-21)

- **SC-1756** — `agenthix front-door on --previews <domain>` reads the preview address beside the files host, turns the front door on with live apps at that address, runs its three checks and says so, and refuses, before anything is asked or changed, an address a preview address cannot be.
