# Scenarios — `relay/`

> Module contract: what `relay/` (the relay, run as a service of hq's compose set on hq's machine, and later on machines of its own) promises the browsers that open files through it, the sites that dial it and the hq that names it. Flat capability list.
> **Scenario ids are unique across every file in this directory**, not per file, because a test cites a scenario by its id alone; the next free id for all of them is `next-sc` in [`hq.md`](hq.md). Ids are append-only: assigned once, never reused or renumbered.
> Written on 2026-10-27 from the finished code at the close of the unit *seeing the agents' work*. The stories these fulfil are US-390 to US-397 in [`../stories/hq.md`](../stories/hq.md) and [`../stories/cross-cutting.md`](../stories/cross-cutting.md). How a ticket is made and checked is in [`core.md`](core.md); how a site reads and serves a file is in [`site.md`](site.md); how hq opens a file is in [`hq.md`](hq.md).

A relay holds nothing and decides nothing: it has no database and no accounts, never makes a ticket or a pass, stores no file, and keeps only its lines and its counters. It never logs a ticket, a path or a query.

## The relay's configuration and its health (added 2026-10-27)

A relay is a fleet member that carries bytes between browsers and the sites assigned to it and decides nothing: hq signs a ticket, the relay passes it down the line a site opened to it, and the site checks it. hq's own relay runs beside hq on hq's machine; its code is the `relay/` module.

- **SC-1468** — The relay refuses to start, in plain words, without hq's address or its secret, and refuses to send its secret in the clear across a network it does not control; it listens on the loopback and the relay's port by default, and takes the app's origin from `HQ_URL` and the files host as hq's web server decides it. · fulfils AC-397a
- **SC-1469** — The files host is never hq's own host and is matched against the `Host` header by name, ignoring the port and letter case. · fulfils AC-397e
- **SC-1470** — The health path answers `ok` on any host and nothing else does.
- **SC-1471** — The relay dials hq with its secret and protocol version, learns its own id from hq's welcome and reports its load every 15 seconds; it ignores a welcome it cannot read or of a protocol too far apart, reconnects after hq drops it and says plainly when hq refuses its secret, and closes every site's line when hq names it anew, since their passes name the old id. · fulfils AC-397a
- **SC-1472** — A site dials its relay with a pass: the line of a site whose pass hq signed for this relay is kept, none is taken before hq has named the relay, a dial with no pass or site id, or with a pass signed by another key, for another relay or expired, is refused, an upgrade on any other path is refused, and a version check that fails after a good pass answers 426 with the relay's own versions. · fulfils AC-397c
- **SC-1473** — The relay keeps one line per site: a new dial takes new streams while the old line is closed once its streams are over (at once when idle, after a grace when busy), a line whose socket closed is forgotten with its streams failed without a displaced socket clearing its replacement, and every line closes when the relay is named anew; each person's streams are counted apart and released once. · fulfils AC-397f
- **SC-1474** — A browser asking for `/t/<ticket>` has the ticket passed to the site the ticket names and gets its file: a download as an attachment and an octet stream whatever the site guessed, a file name that cannot be encoded survived, a content type that is not a plain media type replaced, `Range` and `HEAD` passed on, no cookie or authorisation ever passed to the site, and the site's refusals (forged or expired 403, changed 409, not found 404, range 416, busy 503, failed 500) answered with the security headers. · fulfils AC-397b
- **SC-1475** — Every answer gives CORS to the app's origin only and never with credentials, so no other page can read a file from the relay. · fulfils AC-397e
- **SC-1476** — The relay refuses for itself what is not a ticket request: nothing on any host but the files host and no browser at all without one, 404 for any other path, only `GET` and `HEAD`, 403 for a token that names no site and person, 503 when the site the ticket names holds no line, 502 for a site that sends no valid head and 504 for one that never answers. · fulfils AC-397e
- **SC-1477** — A person may have 16 streams open at a relay at once and the seventeenth is answered 429; the site's stream is cancelled when the browser goes away, and the response is cut when a site sends more than its head promised. · fulfils AC-397f
- **SC-1478** — The relay never logs a ticket, a path or a query. · fulfils AC-397c
- **SC-1479** — An upload ticket for this relay is served from the read-only upload folder with the same headers as a site's file: every kind of upload path, nested attachments included, a range and a `HEAD` without a body, a download as an attachment and an octet stream, and a ticket whose version is not the file's refused. · fulfils AC-397a
- **SC-1480** — An upload ticket cannot do more than name an upload: one made for another relay, signed by another key, expired or for another purpose is refused, so is a path outside the upload patterns or one that steps up, a link — to a file or a folder, inside the folder or out — and a hard link are never followed, a ticket with no person is taken only for a picture shown before sign-in (counted in one bucket), a person is held to 16 streams across uploads and sites alike, and nothing is served, with a plain problem said, when the folder is not there or until hq has named the relay; a ticket or path is never logged. · fulfils AC-397d
- **SC-1481** — On a bare address (no name for files) an upload is sent as an attachment — a download as it is, a text preview as plain text and a picture with its type — and a preview of a kind that needs a files address is refused. · fulfils AC-397a
- **SC-1482** — On a bare address a site's file is passed down the site's line and text answered as plain text as an attachment, a preview of an HTML type or a PDF is refused and the site's stream cancelled, a download is an attachment, and a person is held to the same stream limit. · fulfils AC-397e
- **SC-1483** — The bare door is answered only on the app's own host, not on the files host nor any other, nowhere without the app's origin, and never for a path that is not a ticket under the prefix. · fulfils AC-397e
- **SC-1484** — A download of more than 64 MiB reaches a slow reader whole with the relay holding about a window for it; a stalled browser holds its stream at the window without failing it and it finishes when the browser reads again; another browser is served at full speed while one stream of the same site is stalled; and a site that sends past the window it was given is cut off. · fulfils AC-397f
- **SC-1485** — A ranged download passes from browser to site and back as the site cut it: the whole file, then any range of it, and the site's refusal of a ticket made for another relay. · fulfils AC-390b
- **SC-1486** — The PDF viewer page is served on the files host with its own policy — scripts from its own origin only, framed only by hq — naming hq as the one origin it reports to and loading only its own script and style; it is not served on hq's own host nor any other, nor when the relay knows no hq origin, says so when it was not built into the relay, answers only `GET` and `HEAD` ignoring a query, and drops any cookie. · fulfils AC-397e
- **SC-1487** — The viewer's files — script, style, worker and pdf.js data — are served with their types and policy, the worker alone given WebAssembly (and still no eval), nothing outside what it was built with, no link and no file of unknown type is served, and a copy the browser holds is answered 304. · fulfils AC-397e
- **SC-1488** — A PDF that carries JavaScript runs none of it: the viewer is opened with no XFA forms and none of pdf.js's scripting set up, its bundle holds none of pdf.js's scripting and its script engine is not among its files. · fulfils AC-397e
- **SC-1489** — The viewer takes only a ticket on its own origin from the address fragment (with the theme), reports a changed file, a refused read and a broken PDF as such in one message envelope with a page count, fits a page to the width it has within the zoom's bounds, steps zoom between its bounds and says which page is at the top. · fulfils AC-390b

## Live apps and bundles (added 2026-11-02)

> **Behind the `livePreview` flag, at experimental, so not in the release:** SC-1749 to SC-1753. The product does not keep these promises while the flag is off. The QA model has no mark for a promise outside the release, so this note stands in for one.

Written at the close of the unit *live preview*, from the finished code. The relay carries a live app's requests and WebSockets, and a branch's bundle between two sites; HQ signs every ticket and the site checks each stream again ([`hq.md`](hq.md), [`site.md`](site.md), under "Live preview").

- **SC-1749** — A live app is entered only by a POST navigation from HQ's page, with a ticket HQ signed for that app and this relay, within its time to enter: in HQ's viewer it sets a partitioned host-only cookie holding a handle, never the ticket, and for a new tab a strict cookie entered at the top level; a renewal does not move the page; a ticket is taken once and a replay of a real one counted; an entry from a sibling app's page, a link or with no `Origin`, a ticket for another app or relay, past its time or not signed by HQ, a viewer's ticket entered at the top level and a tab's entered in a frame are refused; a ticket signed before HQ cut its person, its live preview or its app off is refused, and one signed after (it paused and resumed, or started again) is taken. Every `Domain` comes off a cookie the app sets, and one named as the relay's own is dropped. · fulfils AC-416d, AC-421c
- **SC-1750** — The relay carries a live app's requests to its site with the ticket and back with the app's headers, bodies included, and refuses without its cookie, asking nothing of the site and counting nothing for requests with no cookie it gave out; it refuses a sibling app's page, a request without fetch metadata and a navigation from elsewhere, lets through a navigation the person made at the top level, sends one from outside any page to the app's top without carrying it, and does not take one app's cookie at another's address; when HQ says the ticket no longer stands it refuses and forgets the cookie (HQ's yes is kept a moment so a page in a loop does not ask on every stream, while a revocation still cuts at once), counting a refusal for a cookie it held once the entry was cut off; it says the site's refusal in words with its status and ends a response under way when HQ revokes the person. A WebSocket is carried both ways with the subprotocol the app chose, opened only from the app's own page (by its `Origin` when the browser sends no fetch metadata), and closed when HQ revokes the app. · fulfils AC-416d, AC-421c
- **SC-1751** — The relay answers live apps only under the preview pattern it is given (development's for HQ on `localhost`, or none, and it will not start with a pattern it cannot read): it reads the app from the host, answers its own check name under the preview domain itself (sealed, `GET` and `HEAD` only, without any site), refuses a name under the domain that is no app's, leaves every other host to the files door, and answers no preview address with live apps off. · fulfils AC-423a
- **SC-1752** — On its link to HQ the relay asks whether a ticket stands and takes silence, or no link, as no; it passes on a revocation it can read and drops one it cannot, and reports each app's refusals since the last report with the apps' streams beside the files'. · fulfils AC-421c
- **SC-1753** — A bundle ordered by HQ is carried between two sites' lines: the source's head and every byte go to the destination within the source's window; an end that holds no line is reported by name and nothing is opened; the source's refusal never opens the destination; the destination is cancelled when the source breaks part-way, so nothing lands; only a well-formed order is read. · fulfils AC-420b
